# 실제 수업 통합 검증과 팀 결정 항목

현재까지의 자동 테스트는 가짜 입력을 포함합니다. 아래 기록은 실제 수업 프로그램·장치에서 별도로 채우며, 빈칸을 통과 결과로 간주하지 않습니다. 실제 수업 대신 동의받은 모의 회의도 사용할 수 있습니다. 개인 식별이 가능한 화면·음성·전사는 저장소에 올리지 않습니다.

## 10분 동시 실행 검증

1. Windows, Python 버전, CPU·메모리, 전원 상태, 회의 프로그램, 창 크기와 디스플레이 배율, 참가자 타일 수, 오디오 입력 방식을 기록합니다. 모든 참가자의 분석 동의를 확인합니다.
2. 프런트에서 영상 분석·실험 모델·음성 전사를 선택하고 수업을 시작합니다. 한 얼굴 실험 점수가 필요하면 개발자 미리보기에서 정면을 본 뒤 `C` 키로 보정합니다. 다수 얼굴은 현 모델에서 점수 보류가 정상입니다.
3. 10분 이상 수업 화면과 음성을 함께 사용하며 1분마다 상태, 최근 영상 결과 경과, STT 처리 지연·RTF·대기 청크·버린 청크·장치 불연속을 기록합니다. 화면에 표시되는 지연은 최근 청크 기준이며, p50/p95/max는 `LiveTranscription.stats()`를 별도로 수집해야 합니다. STT가 재시작되면 실행기 통계는 초기화됩니다. CPU·메모리·발열도 운영체제 도구로 관찰합니다.
4. 시각을 읽을 수 있는 영상과 동의받은 발화를 기준으로 각 구간의 시작·종료와 전사 시각 차이, 사용자가 화면에서 결과를 본 시각을 별도로 기록합니다. `created_ms - end_ms`는 이벤트 생성까지의 지연이며 화면 표시까지의 지연은 아닙니다. 제안서의 5초 목표는 구간 종료부터 실제 화면 표시까지의 평균으로 평가합니다.
5. 메모를 남기고 수업을 종료합니다. 전사·점수·메모·상태가 같은 세션에 들어왔는지와 마지막 전사가 저장됐는지 확인합니다. JSON을 내보내 다시 열고 원본 미디어와 개인별 중간 특징이 없는지 확인합니다.
6. 별도의 모의 수업에서 영상 창 최소화·복원, 오디오 장치 중단, 수업 종료를 각각 실험해 오류 표시·재시도·다른 모듈의 지속 동작을 확인합니다. 비정상 종료 실험은 보존할 수업 데이터가 없는 모의 세션에서만 수행하고, 재실행 후 사이드바의 복구 버튼으로 마지막 체크포인트를 엽니다.

STT RTF와 처리 지연은 수집된 음성 청크 기준입니다. 실제 발화부터 프런트에 보일 때까지의 지연이나 전사 정확도를 대신하지 않습니다. 한국어 전사 CER은 독립적으로 작성한 정답 전사와 비교하고, 평가 발화와 표기 규칙을 기록해야 합니다.

## 팀에서 합의할 항목

- **다인 집계:** 화면의 검출 수와 수업 실제 참가자 수는 다릅니다. 집계 대상의 정의, 관측 가능 시간, 타일 변화와 가림, 모델이 산출할 수 없는 경우를 정해야 합니다. 화면 좌표·배열 순서는 영구 참가자 ID가 아닙니다.
- **모델 출력:** 실험 점수는 단일 얼굴 상대 머리 각도 기반입니다. 최종 모델의 입력·점수 척도·버전·평가 데이터·보류 기준과 구간 겹침을 정합니다.
- **구간별 신호:** 얼굴 방향, 머리 이동, 표정 형태, 상체 이동 중 실제 사용할 집계의 이름·단위·계산 방법·품질 사유를 정합니다. 공통 `signals`는 합의 전 빈 객체이며 개인별 이력과 원본 랜드마크를 저장하지 않습니다.
- **음성 범위:** 루프백은 기본 출력의 다른 소리도 받으며 교수자 마이크와 동시 수집하지 않습니다. 어떤 소리를 수업 전사 대상으로 할지, 중단·누락 시 전사를 어떻게 표시할지 정합니다.

합의 결과에 맞춰 공통 계약 버전, 검증기, 생산 모듈, 프런트와 저장 형식을 함께 갱신합니다. 위 항목은 구현 완료나 팀 승인으로 취급하지 않습니다.
