# 웹캠 시선과 화면 주시 후보 조사

조사일: 2026-11-12. 아래 도구는 조사만 했으며 새 패키지 설치나 실제 카메라 정확도 비교는 하지 않았다.

후속 상태: 사용자가 지점 보정 없는 대략적인 주시 모델 적용을 요청해,
[MobileGaze MobileOne S0](pretrained-gaze.md)를 독립 Python 데모의 `--gaze`에 연결했다.
WebGazer 브라우저 설계는 이번 방향으로 대체했으며 WebGazer/EyeGestures는 설치하지 않았다.

## 이전 실험과 화면 주시의 차이

이전 `--eye-down-gate`는 MediaPipe 얼굴 랜드마크의 눈꺼풀·홍채 위치를 재사용하는
단일 얼굴 하향 후보 실험이었다. 사용자 요청으로 해당 로직과 옵션을 제거했다.
정확한 화면 안팎 판정은 아직 구현하지 않았다. 대체 기능의 범위는 위 후속 문서를 따른다.
[MediaPipe 공식 설명](https://chuoling.github.io/mediapipe/solutions/iris.html)도
홍채 추적으로 사람이 바라보는 위치를 직접 알아내는 것은 아니라고 명시한다.

정확한 화면 좌표가 필요 없더라도, 화면 주시의 이진 판정에는 화면 경계와 시선 사이의
관계가 필요하다는 것이 이번 검토의 판단이다. 카메라 위치, 화면 크기와 거리, 머리 자세가
달라지므로 단순히 홍채가 가운데라는 조건을 화면 주시의 정답으로 쓰기는 어렵다.

## 후보 비교

| 도구 | 공식 기능 | 이 프로젝트에서의 판단 |
|---|---|---|
| [MediaPipe Iris](https://chuoling.github.io/mediapipe/solutions/iris.html) | 홍채·눈 윤곽 추적. 주시 위치 자체는 제공하지 않음 | 기존 랜드마크 재사용으로 추가 추론 없이 방향 후보를 실험하기 적합 |
| [EyeGestures](https://github.com/NativeSensors/EyeGestures) | 일반 카메라 기반 시선 추적, 보정 및 좌표 API, Python/웹 | 개인 웹캠 보정 실험의 후보. 저장소에 기존 v3 예제가 있어 참고 가능하나 최신 API 호환은 검증 필요 |
| [WebGazer.js](https://webgazer.cs.brown.edu/) | 브라우저에서 눈 특징과 클릭 위치를 학습해 화면 좌표 추정. 클라이언트 실행 | 참가자별 보정 페이지를 만들 수 있을 때 후보. 기존 Python 창 캡처에 바로 교체하는 방식은 아님 |
| [GazeTracking](https://github.com/antoinelame/GazeTracking) | 동공 위치, 좌우·중앙과 수직/수평 비율 API | 방향 비교용. 화면 경계 판정은 별도로 보정하고 검증해야 함 |

추가 소스 검토: [EyeGestures v4 엔진](https://github.com/NativeSensors/EyeGestures/blob/main/engine/src/eyegestures.rs)은
예측 x/y를 화면 너비/높이 안으로 clamp해서 반환한다. 따라서 공개 반환 좌표의 경계 포함 여부만으로
화면 밖 주시를 판정하면 항상 화면 안으로 나오는 오류가 생긴다. 화면 경계 값은 불확실로 두어야 하며,
화면 밖까지 분류하려면 잘리기 전 좌표를 제공하는 API/엔진 수정 또는 별도 분류 검증이 필요하다.
단순 패키지 교체만으로 화면 주시 여부 판별이 완성된다고 설명하지 않는다.

EyeGestures 공식 README는 v4 Rust 기반 엔진으로의 이전과 기존 Python 엔진 폐기를 안내하며,
예제에 v3/v4 이름이 혼재한다. 현재 저장소 `video_recognition/eye_gestures_demo.py`도
v3를 가져오므로 그대로 최신 패키지와 호환된다고 가정하지 않는다. 공식 저장소 라이선스는 GPL-3.0이다.
카메라에서 멀어지면 반응이 떨어질 수 있다는 안내도 있다.
WebGazer 공식 페이지는 2026-02-24부터 업데이트를 보장하지 않는다고 안내한다.

## 권장 진행 순서와 검증

개인 웹캠의 실제 화면 주시 후보가 필요하면 EyeGestures를 별도 환경에서 먼저 비교하는 방안을 권한다.
브라우저에서 참가자별 보정을 받을 수 있다면 WebGazer도 비교 후보이다. 어느 도구든 화면 중앙과
모서리 보정 후 보정에 쓰지 않은 화면 안·왼쪽 밖·오른쪽 밖·위·아래 응시로 검증해야 한다.
화면 경계 주변과 검출 불가는 `unknown`으로 두고, 지속 시간과 경계 여유를 적용한다.
잘못된 화면 밖 판정 비율, 검출 가능 시간 비율, 처리 지연을 함께 측정해야 한다.

교수자가 캡처한 수업 창의 여러 작은 얼굴에는 참가자별 화면·카메라 관계가 없고 눈 픽셀이 부족할 수 있다.
한 사람의 보정을 모든 참가자에게 적용할 수 있다고 가정하지 않는다.
시선 후보를 실제 집중·이해도의 판단으로 사용하지 않는다.

추가 개발 시에도 원본 영상·눈 이미지·개인별 시선 이력을 새로 저장하지 않고,
세션 계약을 변경해야 한다면 별도 검토한다.
