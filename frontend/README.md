# 교수자 대시보드

기존 Windows 영상 분석 작업(`LiveSession`)과 공통 `IntegrationService`를 사용하는 Streamlit 화면입니다. Figma의 세션 시작 준비, 라이브 세션, 사후 검토를 연결합니다.

## 실행

저장소 루트에서 같은 Python 환경에 영상 분석, 프런트, STT 의존성을 설치하고 한국어 모델을 한 번 내려받습니다.

```powershell
python -m pip install -r video_recognition/requirements-integrated.txt
python -m pip install -r frontend/requirements.txt
python -m pip install -r faster_whisper_stt/requirements.txt
python -m pip install -r ai_agent/requirements.txt
python -m streamlit run frontend/app.py
```

실시간 창 캡처는 Windows 전용입니다. Windows 외 환경에서도 준비 화면과 저장 JSON의 사후 검토는 사용할 수 있습니다.

### Gaussian + 재식별 다인 점수

프런트의 기본 관찰 점수는 Gaussian입니다. 준비 화면에서 **영상 분석 사용**, **관찰 점수 사용**,
**세션 내 얼굴 재식별 사용**을 함께 선택하면, 확정된 임시 ID마다 정면 보정과 Gaussian 점수를
별도로 계산합니다. 재식별을 끄면 신원 확인 없이 단기 위치 트랙별로 계산합니다.

프런트의 머리 각도는 MediaPipe 얼굴 변환행렬에서 구하며 행렬이 없거나 유효하지 않으면 점수를 보류합니다. 현재 5초 집계와 아래 보기 감점은 버전이 구분된 임시 실험 설정입니다. 다인·수업 창에서의 각도 정확도는 별도 평가가 필요합니다.

재식별은 기본 영상 환경에 다음 선택 패키지가 추가로 필요합니다.

```powershell
video_recognition/.venv/Scripts/python.exe -m pip install -r video_recognition/requirements-reidentification.txt
video_recognition/.venv/Scripts/python.exe -m streamlit run frontend/app.py
```

InsightFace가 처음 실행될 때 buffalo_l 모델을 받으며 네트워크와 준비 시간이 필요할 수 있습니다.
패키지·모델 로딩 또는 추론에 실패하면 UI에 사유를 표시하고 개인별 점수를 보류합니다.
수업 영상과 STT는 별도로 계속 실행합니다. 모델 라이선스와 설치 설명은
[재식별 안내](../video_recognition/README.md)를 참고하세요.

- ID가 확정되면 해당 얼굴의 안정된 머리 각도를 약 3초 수집합니다. 실제 정면인지는 검증하지 못하므로
  모두 정면을 유지해야 합니다. **정면 기준 재보정**은 현재 관측된 ID의 기준을 다시 수집합니다.
- 라이브의 **세션 내 ID별 Gaussian 점수** 표에 ID·상태·보정과 현재 머리·눈·결합 점수를 표시합니다. 표는 시점별 임시 관측값이며 상단의 최근 5초 그룹 집계와 다릅니다. 미검출·ID 미확정·보정 중·기준 점수가 없는 아래 보기 보류는 0점이 아닙니다. 직전 유효 점수가 있으면 아래 보기 5초 유예 후 머리 점수가 초당 7점씩 0점까지 감소합니다. ID 미확정 얼굴은 개인 표에 추가하지 않습니다.
- 라이브 그룹 점수는 머리 방향 70%와 눈 감김 30%를 결합합니다. 개발자 창의 개인 결합 점수 평균과 세션 이벤트의 사람·시간 가중 그룹 집계는 계산 방식이 다릅니다. 눈 또는 머리 관측이 부족하면 해당 관측을 보류합니다.
- 같은 ID가 복귀하면 완료된 기준은 유지하되 시간 상태를 새로 시작합니다. 과거 점수를 현재 점수로 유지하지 않습니다.
  임시 상태는 최대 32명/마지막 확인 후 120초까지 보관하고 수업 종료 때 지웁니다. 이후 복귀는 새 ID가 될 수 있습니다.
- 개발자 프리뷰에 ID를 표시합니다. 프리뷰를 꺼도 재식별·점수화는 계속하며, 표시할 때 추론을 다시 하지 않습니다.
- 상단 점수·그래프·강의 조교·사후 검토에는 **유효 관측된 사람·시간의 그룹 집계 이벤트**를 사용합니다.
  전체 수강생의 참여율이나 모든 사람의 평균이 아닙니다. 개인 표와 달리 그룹 이벤트만 JSON에 저장합니다.
- 임시 ID·임베딩·개인별 점수 이력·얼굴 이미지는 JSON/체크포인트/성능 로그에 추가하지 않습니다.
  저장 세션을 다시 열어도 개인 표는 복원되지 않습니다. MobileGaze 시선 실험은 이 연결에 포함하지 않습니다.

다인 보정·그룹 산정식과 한계는 [모델 문서](../engagement_model/README.md#프런트-다인-gaussian)를 참고하세요.
실제 Windows 수업 창·작은 얼굴·가림·교차에서의 ID 정확도와 점수 타당성은 별도 장치 검증이 필요합니다.

## 화면과 데이터 연결

- 준비 화면의 **제안·화면 알림 기준 관찰 점수**는 자동 제안과 라이브 점수 경고에 함께 적용합니다. 현재 유효 점수가 기준 이하이면 그래프를 빨간색으로 표시하고 화면에 확인 안내를 띄웁니다. 점수 카드 배경은 고정 구간으로 60점 미만 빨강, 60점 이상 80점 미만 노랑, 80점 이상 초록입니다. 관측 불가나 이전 점수 임시 유지 중에는 회색으로 표시하고 저하 경고를 띄우지 않습니다. 색상은 화면의 참고 구분이며 집중도 판정이 아닙니다. 설정은 수업 중 브라우저 세션에만 유지됩니다.
- 수업 중 새 자료·강의 제안은 화면 팝업 알림으로 한 번 표시하며, 제안 내용과 근거는 강의 조교 카드에서 다시 확인합니다. 자동 갱신 주기는 1초이며 실제 제안 생성 시간은 별도입니다. 라이브와 사후 검토의 전사는 시간순으로 이어서 표시하고, 사후 구간별 점수·수정과 연결 제안은 별도 펼침 영역에서 확인합니다.

- **세션 시작 준비**: 수업 제목과 분석·저장 동의를 확인하고 영상 분석, 관찰 점수, 음성 전사를 선택합니다. 영상 분석을 사용할 때 수업 창을 선택합니다. 음성만 사용하는 경우 창 선택은 필요 없습니다. 강의 자료(PDF·PPTX)를 올리고 로컬 또는 OpenAI·Gemini·Claude 개인 API 키로 문장 작성 방식을 선택합니다. 외부 제공자에는 전사·메모·자료 일부가 전달됩니다. 설정은 수업 시작 전에 정합니다.
- **전사 모델 선택**: 준비 화면에서 faster-whisper small(기본) 또는 base를 선택합니다. 이전에 쓰던 sherpa-onnx 스트리밍 모델은 강의 녹화 음성(데모 영상)을 거의 인식하지 못해 제거했습니다(측정 기록은 [faster_whisper_stt/README.md](../faster_whisper_stt/README.md)). faster-whisper는 첫 사용 시 모델 다운로드가 필요할 수 있습니다. 말이 멈추는 지점(8~20초)마다 구간을 겹치지 않게 한 번씩 처리한 결과를 확정 전사로 보내므로 부분 전사는 표시하지 않고 구간 수집과 추론 시간만큼 늦게 나타납니다. 무음 구간은 인식하지 않고 VAD와 지어낸 문장 거르기를 적용하지만 오인식·누락은 남을 수 있습니다. 종료 시 남은 짧은 구간도 처리합니다. 강의 자료를 올리면 여러 쪽에 반복되는 용어를 준비 화면에 표시하고 faster-whisper 전사 힌트로 넘깁니다(처리 시간 증가, 세션 JSON에는 저장하지 않음). 전사의 시간은 발화별 정밀 시각이 아닌 구간 전체입니다. 결과를 강의록에서 확인·수정하세요.
- faster-whisper 진단은 최근 약 2초 오디오 청크 RMS의 최대값(dBFS), 처리 구간 수와 빈 결과 수를 표시합니다. 성능 로그를 켜면 동일한 수치도 저장합니다. 입력 신호가 작으면 Windows 기본 출력 장치와 재생 앱의 출력 장치 및 음량을 확인하고, 신호가 있는데 빈 결과가 많으면 모델 입력과 인식 결과를 비교합니다. RMS만으로 말소리인지 판정하지 않습니다.
- 창 목록은 준비 화면에서 처음 불러온 뒤 유지합니다. 새 창을 열거나 닫았을 때 **창 목록 새로고침**을 누르면 목록을 다시 읽고, 기존 창이 여전히 있으면 선택을 유지합니다. 앱 자체의 프리뷰 등 같은 프로세스의 창은 수업 창 목록에서 제외합니다.
- **강의 조교 연결**: 수업 시작 시 `ai_agent.LiveAssistant`를 같은 `IntegrationService`와 세션 ID로 시작합니다. 확정 전사와 최근 유효한 모델 점수가 필요하며 점수가 설정값 이하일 때 제안합니다. 외부 AI는 자료 유무와 무관하게 전사와 자료 후보를 활용합니다. AI 검색어가 있으면 한국어 위키백과 검색 결과 제목과 링크를 표시하며 본문과 정확성은 확인하지 않습니다. 검색어가 위키백과로 전송됩니다. 수업 종료 시 조교도 멈춥니다.
- 제안 카드에는 제목과 내용을 먼저 표시하고, 모델·출처·근거 전사와 조교 상태는 펼쳐서 확인합니다. 수동 제안의 모델과 저장 여부도 세부 사항에서 확인할 수 있습니다.
- **라이브 세션**: 점수·정면 보정, 조교 제안, 타임라인, 최신순 전사, 메모와 분석 상태를 표시합니다. 제안 상세에 수동 요청과 출처·근거를 모았습니다. 좁은 화면에서도 나란히 배치된 카드는 두 열을 유지하며, 타임라인 카드 안에서는 제목 아래에 최근 점수를 표시합니다. 점수가 없으면 0점으로 바꾸지 않고 사유와 이전 참고 점수를 구분합니다. **제안 요청**은 최근 60초 확정 전사와 관련 자료로 한 번 요청하며 결과는 화면에만 표시합니다.
- 실시간·사후 그래프는 각 세션의 `engagement_window.payload.model_output`을 표시합니다. 라이브 그래프 끝의 점은 점수 카드와 동일한 최신 표시값이며, 임시 유지값은 별도 마름모입니다. 예전 점수를 현재 모델로 다시 계산하지 않으며, 회색 영역은 점수 없는 분석 창 전체를 표시하므로 서로 겹친 창이 있으면 실제 점수 공백보다 넓을 수 있습니다.
- 사후 분석에서는 현재 브라우저 세션에서 시작한 동일 수업의 외부 AI 제공자·모델·키를 재사용할 수 있습니다. 키는 세션 메모리에만 보관하며 세션 JSON에 저장하지 않습니다. 앱을 다시 시작하거나 다른 수업을 열면 별도로 입력해야 합니다.
- 라이브 화면은 제목 오른쪽에 정면 기준 재보정과 수업 종료 버튼을, 제목 아래에 수업 상태·진행 시간·보정 상태를 표시합니다. 왼쪽에는 공통 타임라인과 최근 점수를 함께 표시하고, 오른쪽 제안 카드는 타임라인과 같은 높이로 늘어납니다. 그 아래 전체 너비에 높이를 넓힌 교수자 메모를, 다음 행에 실시간 전사와 개발자 도구를 나란히 배치합니다. 라이브 카드와 진단은 하나의 주기 갱신 영역에서 같은 스냅샷으로 1초마다 갱신합니다. 메모는 Shift+Enter로 줄을 바꾸고 Enter 또는 입력칸의 전송 버튼으로 저장합니다. 개발자 모드·성능 로그·재보정·제안 처리 버튼은 상태 변경 콜백으로 처리하며 전체 앱의 명시적 재실행을 요청하지 않습니다. 도구 전환 시 카드 위치와 그래프 범위를 유지합니다. 수업 종료·페이지 이동은 전체 화면 전환을 수행합니다. 실행 상태 표시의 유무에 따라 본문 여백을 변경하지 않습니다.
- 카드 내부 간격은 Streamlit의 `container(gap='xsmall')`로 지정하며, 타임라인 카드는 `xxsmall`을 사용합니다. 수업 제목은 시간 표시의 도움말에서, 긴 점수 사유와 이전 참고 점수는 점수 사유의 도움말에서 확인합니다. `gap` 인자가 없는 구버전에서는 기본 간격을 사용합니다.
- **사후 검토**: 종료 수업을 다시 열거나 공통 계약 세션 JSON을 가져옵니다. 타임라인으로 전사·메모·자료·피드백을 함께 필터링합니다. 선택 구간의 전사는 테두리 없는 행 단위 영역으로 표시하며 여백으로 구간을 구분합니다. 왼쪽에는 시간·관찰 점수·직전 변화·관측 품질, 오른쪽에는 전사와 도착 시점에 한 번만 배치한 연결 제안을 줄글로 표시합니다. 전사는 각 영역에서 수정할 수 있습니다. 사후 분석의 자료·수업 제안은 확정 전사가 있고 낮은 관찰 점수나 교수자 메모가 있는 5분 구간에서 생성합니다. 체크박스를 사용하면 현재 선택한 검토 구간도 추가됩니다. 이미 제안된 구간은 중복 생성하지 않으며, 구간별·전체 피드백은 별도로 만듭니다. 점수가 없으면 낮은 점수로 간주하지 않습니다.
- 검토 구간 선택기는 수업 상대 시간을 `시:분:초`로 표시합니다. 선택 눈금은 기본 1초이며 긴 수업에서는 눈금 수를 제한하기 위해 간격이 커질 수 있습니다. 그래프나 점수 구간에서 선택한 경계와 세션 저장 시간은 밀리초 단위로 유지합니다.
- 전사와 점수는 별도 열에 나란히 표시합니다. 전사 종료 시점까지 완료된 최신 점수 구간이 5초 이내일 때 연결하고, 관측 불가 구간은 건너뛰지 않습니다. 점수는 발화만의 결과나 인과관계가 아닙니다. 중첩된 롤링 구간은 유효 점수의 이벤트별 평균과 범위를 표시합니다.
- 사후 강의록에서 근거로 연결된 제안의 제목과 생성 시점(수업 중/수업 후)을 확인할 수 있으며, 제안에서 근거 전사를 펼칠 수 있습니다. 제안의 시각 또는 근거 전사가 선택 구간에 겹치면 표시됩니다. 수업 중 화면에서 숨긴 제안도 저장된 기록에서는 볼 수 있습니다. 전사 수정으로 기존 근거 ID가 사라지면 자동으로 새 전사에 연결하지 않고 재확인 안내를 표시합니다.
- 전사 수정은 기존 발화의 구간과 ID를 유지하는 `transcript_edited` 이벤트로 전달합니다. 기존 근거가 바뀐 자료/피드백에는 재확인 안내를 표시합니다.
- 세션 저장은 통합부의 원자적 저장을 사용합니다. 메모 목록을 별도로 다시 합치지 않으므로 불러오기/재저장 시 메모가 중복되지 않습니다.

### 로컬 기록 위치

기본 경로는 사용자 홈의 `lecturer_dashboard/sessions/`입니다. `LECTURER_SESSION_DIR` 환경변수로 변경할 수 있습니다. 수업 종료 시 자동 저장하며, 재실행 뒤 지난 수업 목록에서 열 수 있습니다. JSON 가져오기는 공통 계약 검사를 통과한 파일만 저장하며, 동일 세션 ID가 있으면 기존 파일을 유지합니다. 삭제는 이 앱의 기록만 제거하고 별도 다운로드 파일에는 영향을 주지 않습니다.

진행 중에는 같은 폴더의 `.recovery/`에 15초마다 공통 계약 JSON을 저장합니다. 비정상 종료 후 앱을 다시 열면 사이드바의 **복구** 버튼으로 마지막 복구 지점까지 사후 검토할 수 있습니다. 누락된 마지막 15초와 미확정 전사, 원본 영상·음성은 복원되지 않으며 실시간 분석도 재개하지 않습니다. 정상 저장이 완료되면 복구 파일을 삭제합니다. 같은 세션 ID의 일반 저장 파일이 이미 있으면 덮어쓰지 않고 복구 파일을 유지합니다. 복구용 파일도 전사와 메모를 포함하므로 로컬 기록으로 관리해야 합니다.

### 모듈 연결 상태와 제한

- 수업 삭제는 해당 ID의 일반 JSON과 `.recovery` 복구본을 함께 제거합니다. 복구본 삭제에 실패하면 일반 기록을 유지하고 오류를 표시합니다. 같은 ID의 수업이 진행 중이면 종료 후 삭제해야 하며, 별도 다운로드 파일과 진단 로그는 자동 삭제하지 않습니다.

- 영상 캡처·MediaPipe는 기존 `LiveSession` 경로를 사용합니다. 분석 입력은 종횡비를 유지해 최대 1920×1080으로 축소하고, 얼굴 검출·존재 신뢰도 기준은 각각 0.3입니다. 전체 화면과 겹침 영역 외에 화면 경계로 찾은 후보 영역도 분석합니다. 후보가 불명확해도 전체·겹침 영역 분석은 유지하며, 추가 추론의 지연을 실제 수업 환경에서 확인해야 합니다. 입력 크기는 개발자 진단에서 확인할 수 있습니다.
- 라이브 세션은 Gaussian 실험 모델 결과를 `engagement_window`로 전달합니다. 재식별 여부에 따라 ID 또는 위치 트랙별로 보정하고 최근 5초 그룹 구간을 1초마다 발행합니다. 보정 중이거나 관측 불가인 트랙은 점수에서 제외합니다. 점수는 집중도·이해도를 나타내지 않습니다.
- 점수 보류 시 마지막 유효 점수를 최대 15초 동안 표시하고 이전 점수임과 경과 시간을 알립니다. 실시간 그래프 끝에도 같은 값을 별도 마름모로 표시합니다. 모델 오류·종료 또는 유지 시간 경과 시에는 측정 불가로 표시합니다. 보류 구간은 관측 불가로 유지하고 기록·자동 제안에 유지 점수를 사용하지 않습니다. 사후 그래프는 저장된 실제 이벤트만 표시합니다.
- 라이브 세션은 faster-whisper 실행기를 같은 `IntegrationService`와 세션 ID로 실행합니다. 전사는 계약 이벤트로 라이브 화면에 반영되며 확정 전사만 세션 JSON에 저장합니다. 종료 시 STT를 먼저 멈춰 마지막 구간을 처리한 뒤 세션을 종료합니다. 선택한 모델은 수업 시계 시작 전에 불러와 재사용합니다. 모델 준비 시간이 길거나 다운로드가 실패할 수 있습니다. 세션 설정 `stt_model`에는 선택한 모델과 입력(`loopback`/`microphone`)을 기록합니다.
- 라이브 화면의 분석 상태 카드와 상세 진단에는 최근 STT 청크 처리 지연, 대기 청크, RTF와 영상 결과 경과 시간을 표시하고, 버린 청크나 장치 불연속이 있으면 경고합니다. 이 값은 실행 중 진단값이며 화면 표시까지의 전체 지연을 측정한 값은 아닙니다. 청크 번호 누락과 2초 이상 STT 처리 지연은 통합부의 상태 이벤트로도 전달합니다.
- 라이브 화면의 **분석 상태 · 개발자 도구 → 성능 로그 수집 시작**을 누르면 5초 간격 JSONL을 `frontend/diagnostic_logs/`에 기록하고, 중지 버튼이나 수업 종료 시 수집을 멈춥니다. 미리보기 활성화와 별개로 켤 수 있습니다. 기본적으로 꺼져 있으며 로그 폴더는 Git에서 제외합니다. 프로세스 CPU(`100%`는 논리 코어 하나 기준), 작업 집합 메모리, 영상 분석 주기·크기, STT RTF·지연·대기열·손실 수, 모듈 상태와 전사 이벤트 건수·마지막 이벤트 경과 시간만 남깁니다. 전사 내용, 영상·음성, 얼굴 특징, 모델 점수, 수업 제목과 세션 ID는 기록하지 않습니다. CPU는 전체 프런트 프로세스 합계여서 영상과 STT를 분리하지 못하며 로그 자체에도 적은 부하가 있습니다. 로그는 수동 삭제해야 합니다.
- 수업 세션과 영상·음성 작업의 종료를 분리합니다. 영상 오류가 나도 음성과 수업 타이머가 유지되고, STT 오류가 나도 영상 분석이 계속됩니다. 영상·STT·관찰 점수 모델은 실패 시 각각 1초, 2초, 4초를 기다려 최대 3회 재시작합니다. 한도를 넘으면 사용 불가와 사유를 표시합니다. 재시도 횟수는 각 실행 동안 누적하며 수업 종료 시 대기는 즉시 중지됩니다.
- 전사가 중단된 발화의 미확정 결과는 제거하고 이미 확정된 전사는 유지합니다. 실패 구간의 음성이나 점수를 복원하지 않습니다. 영상 작업 재시작 시 정면 기준을 다시 자동 수집합니다. 수집 완료 후 얼굴 소실이나 복수 얼굴 등으로 기준이 무효화되면 상태를 확인하고 라이브 화면의 재보정 버튼을 누릅니다. 모델만 재시작하면 점수 유지 시간과 구간 집계가 새로 시작됩니다.
- 영상 재연결은 기존 창 핸들을 사용하며 창을 닫고 다시 열어 번호가 바뀌면 새 수업 연결이 필요할 수 있습니다. 수업 중 모듈 설정 변경이나 프로세스 자체가 종료된 경우의 복구는 지원하지 않습니다.
- 전사에는 `faster_whisper_stt/requirements.txt`가 필요하고, 선택한 모델은 첫 사용 시 `faster_whisper_stt/models/`에 내려받습니다. 준비 화면은 패키지 설치만 점검하며 모델 다운로드 완료 여부나 실제 실행 성공은 보장하지 않습니다. 실행 실패 시 영상 분석은 계속하고 STT 상태를 `unavailable`로 기록합니다.
- 프런트 루프백은 기본 출력 장치의 전체 소리를 캡처합니다. 수업 소리 외 다른 앱·알림음도 전사되거나 전송될 수 있으므로 수업 전에 재생 장치를 확인하세요. 영상 창 선택과 오디오 입력은 별개이며 마이크와 루프백 동시 수집은 지원하지 않습니다.
- 업로드 자료는 현재 브라우저 세션 메모리에서 강의 조교 색인으로만 쓰며 파일로 영구 저장하지 않습니다. 세션 JSON에는 자료 이름·페이지 번호와 제안 문장만 남습니다. 앱을 다시 시작한 뒤 사후 분석을 하려면 자료를 다시 올려야 합니다. 동작·한계는 [강의 조교 안내](../ai_agent/README.md)를 참고하세요.
- 참여 점수는 `payload.model_output.value`와 기존 점수 키를 지원합니다. 숫자가 없거나 품질이 `not_observable`이면 0점으로 대체하지 않습니다.
- 이동 구간이 겹치면 유효한 롤링 점수를 이벤트마다 한 번씩 평균합니다. 이는 수업 시간의 분석 가능률이 아닙니다. 중첩되지 않는 이벤트는 유효 구간 길이로 가중 평균합니다.
- 신호 레인과 변화 알림은 세부 이벤트 형식이 확정되지 않아 시안의 정적 예시를 표시하지 않습니다. 현재 사후 요약 지표의 건수는 실제 자료 제안 수입니다. 강의 요약은 생성 모듈 연동 전입니다.
- 자료 제안의 숨김/메모 저장 후 숨김은 현재 브라우저 세션의 표시 상태입니다. 제안 자체의 계약상 상태를 변경하지 않습니다.
- 전사는 같은 `LiveSession.service.receive_event()`에 전달되며 세션 JSON에 저장됩니다. 별도 프로세스와의 HTTP/WebSocket 연결은 없습니다.

## 검증

```bash
python -m unittest discover -s frontend/tests -v
```

회귀 검증: 실제 시각/2시간 세션 축, 같은 시각의 숫자와 null 점수, 잘못된 점수, 구간 교차, 전사 수정·메모 저장 후 반복 저장/재열기, 저장 경로, 준비/검토 화면, 공통 스냅샷을 읽는 라이브 화면.

개발자 모드는 웹캠 모델 데모와 공통 패널을 사용합니다. 수업 중 **분석 상태 · 개발자 도구 → 개발자 모드 켜기**를 누르면 실제 분석 프레임과 모델 결과가 별도 창에 표시됩니다. `V`는 오버레이, `[`·`]`는 상세 페이지, `C`는 재보정, `Q`는 창 숨기기입니다. 단일 얼굴일 때 기준점 변화량도 상세 페이지에서 확인할 수 있으며, 이 수치는 진단용으로 점수에 반영하거나 세션 JSON에 저장하지 않습니다. 다인 모드에서는 점수가 전체 집계입니다.

프런트 구간 점수는 머리·눈을 모두 관측한 얼굴의 결합값을 집계합니다. 얼굴 트랙을 확인하면 정면 기준을 자동 수집합니다. 보류 중에는 마지막 유효 구간 점수를 이전 참고값으로 표시하며 보류 구간의 이벤트 값은 null입니다.

### 얼굴 누락 시 정면 기준 복구

재식별을 끈 프런트는 검출된 얼굴별 임시 위치 트랙으로 각각 보정합니다. 같은 트랙이 1초 이내에 안정된 위치로 돌아오면 완료된 정면 기준은 유지하지만, 0.5초를 넘긴 누락 구간의 점수 이력은 초기화해 누락 시간을 점수에 포함하지 않습니다. 1초를 넘긴 누락이나 큰 이동은 해당 기준을 다시 수집하며, 얼굴의 동시 이탈·등장, 겹침, 긴 관측 공백은 연결이 모호하므로 기준을 다시 수집할 수 있습니다. 보정 수집 중 잠깐의 품질 저하는 기존 유효 표본을 유지하지만, 유효 표본 간격이 1초를 넘으면 수집을 다시 시작합니다. 임시 위치 트랙은 신원 확인이 아니므로 같은 자리에서 참가자가 교체된 경우에는 변화가 감지되지 않을 수 있습니다.

라이브 화면의 **분석 상세 상태**에서 관측 중인 임시 트랙 또는 ID를 선택해 해당 대상만 재보정할 수 있습니다. 전체 재보정 버튼도 유지합니다. 개별 재보정 중 해당 대상은 점수에서 제외하고 다른 대상의 보정과 기존 그룹 구간 이력을 유지합니다. 각 대상이 실제 정면을 바라보는지는 자동으로 확인하지 못합니다.

재식별 다인 모드는 확정된 ID마다 별도 기준을 두고, 복귀가 3초 이내이며 같은 ID로 확인되면 기준을 유지합니다. 점수 관측 이력의 즉시 복구는 같은 트랙의 0.3초 이내 누락에만 허용하며, 그보다 길거나 트랙이 바뀌면 다시 쌓습니다. 마지막 유효 관측 이후 3초를 초과하면 같은 ID라도 자동으로 새 기준을 수집합니다. ID 미확정일 때 점수를 만들지 않습니다. 인식된 얼굴이 없거나 기준 수집 중인 시간은 관측 불가로 처리합니다. 재식별은 별도 선택 기능이며 위치 트랙만으로 신원을 확정하지 않습니다. 느린 분석에서 자동 수집이 반복되면 `calibration_frame_gap`과 처리 속도를 확인하세요.

### Gaussian 전용·상체 측정 제거

영상 분석은 얼굴 머리 각도·눈 상태 기반 Gaussian만 사용하며 Legacy/Huang과 상체 pose 측정·표시는 제거했습니다. 재식별과 위치 트랙별 다인 계산, 익명 그룹 집계 저장은 유지합니다.

라이브 카드 재배치와 도구 전환의 재현·검증 범위는 [라이브 대시보드 검토](../docs/live-dashboard-review.md)를 참고하세요.
