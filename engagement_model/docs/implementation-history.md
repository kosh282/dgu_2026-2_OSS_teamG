# 참여도 모델 — 1단계 구현

## Gaussian 각도 공간 개선 모델

웹캠 단축키는 **웹캠 영상 창을 클릭해 포커스를 준 뒤** 입력합니다. 최초 정면 보정은
영문 `C` 또는 `Space`로 시작합니다. 한글 입력 상태에서는 영문 C로 인식되지 않을 수 있습니다.
`collecting` 진행률과 입력 문제 사유가 표시되며 정면을 약 3초 유지하면 `ready`가 됩니다.
키 반복 입력은 억제하며 collecting 중에는 추가 시작 요청으로 수집을 초기화하지 않습니다.
영상 왼쪽 아래 `CLICK TO CALIBRATE` 버튼으로도 시작할 수 있습니다.
`--calibrate` 옵션은 키/마우스 없이 실행 직후 정면 보정을 시작합니다.

### 중립 각도 완화 (angle-time-0.3)

현재 `video_recognition/webcam_test.py`의 실험 점수는 별도 모델이 아니라
`EngagementRuntime(ModelConfig())`, 즉 legacy 모델입니다. 같은 머리 각도·스무딩·정면 보정을
사용하며 Yaw ±2도 데드밴드, 2~15도 구간 0.75배 완화를 어댑터에서 적용합니다.
legacy 상태 기준은 완화 후 Yaw 정면 ±15도/이탈 30도, Pitch 정면 ±10도/위쪽 이탈 -20도,
아래 보기 +15도(해제 +10도)입니다. 정면은 90점에서 5초 동안 100점으로 증가하고,
이탈은 3초 유예 뒤 각도·지속시간으로 감소합니다. 이 규칙은 Gaussian 논문 식이 아닙니다.

Gaussian 기본은 `softened` 모드입니다. `input_adapter.soften_angle()`로 기존 Yaw 완화식을
공유하고 Pitch 점수 입력에도 같은 연속 홀함수를 사용합니다. Pitch의 데드밴드 2도,
0.75배, 완화 경계 10도는 프로젝트 실험값이며 논문 값이나 legacy Pitch 전처리는 아닙니다.
큰 각도의 기울기는 1을 유지합니다. sigma는 15/20도를 유지합니다.

```text
h(a; d,k,b) = sign(a) * [k*(min(|a|,b)-d) + max(0,|a|-b)]  (|a|>d)
             0                                             (|a|<=d)
P_eff = h(P; 2, 0.75, 10)
Y_eff = h(Y; 2, 0.75, 15)
S = 100*exp(-0.5*((P_eff/15)^2+(Y_eff/20)^2))
```

상태 분류와 하향 전이/looking_down 정책은 그대로이며 완화된 Pitch로 보류를 회피하지 않습니다.
기존 상대각/상태를 덮어쓰지 않고 `gaussian_observation`에 점수 계산 입력만 둡니다.
런타임과 publisher는 이 입력을 한 번만 계산·집계합니다. 전처리를 두 번 적용하지 않습니다.
모델/config/발행 확장 버전은 `angle-time-0.3`/`gaussian-angle-time-0.3`/`angle-time-window-3`입니다.
확장에는 재현에 필요한 각도 모드·완화 설정을 기록하며 공통 JSON 구조는 유지합니다.

기존 0.2 비교 모드는 `ModelConfig.gaussian(gaussian_angle_mode='relative')` 또는
웹캠 `--gaussian-angle-mode relative`로 선택합니다. 기본 화면에는 현재 점수, 10초 점수,
완화 전 상대 P/Y, sigma, 행동 상태·보정 상태를 표시합니다. D의 USED P/Y는 실제 계산 입력입니다.
급락 기록은 계속 원본·스무딩·상대각과 실제 입력을 따로 보관합니다. 비정상적인 각도 추정이나
실제 좌우 비대칭을 이번 완화로 해결했다고 간주하지 않습니다.

100ms 간격 동일 합성 입력 비교(실제 행동 정확도 검증 아님):

| 입력 | legacy 점수 | 기존 Gaussian 현재 | 개선 Gaussian 현재 |
|---|---:|---:|---:|
| 정면 10초 | 100 | 100 | 100 |
| Yaw ±10도 | 100 | 88.2 | 95.6 |
| Pitch ±5도 | 100 | 94.6 | 98.9 |
| Yaw 60도 약 10초 유지 | 5.3 | 1.1 | 2.4 |
| 정면 복귀 첫 관측 | 90 | 100 | 100 |

legacy는 규칙·시간 기반 점수이고 Gaussian 현재 점수는 순간 방향 점수이므로 같은 의미의
수치로 해석하지 않습니다. 두 Gaussian의 10초 집계는 짧은 움직임을 완화하고 지속 이탈에
점진적으로 수렴합니다. 정면 복귀 즉시 집계까지 100점이 되는 것은 아닙니다.

### 하향 전이 보류와 비대칭 진단 (angle-time-0.2)

Gaussian 식과 sigma 기본값(15/20도), 10초 시간 커널은 유지하고 관측 선택 정책만 변경했습니다.
상대 Pitch가 `gaussian_down_transition_pitch_degrees`(실험 기본값 10도)를 초과하면
`downward_status=transition_uncertain`으로 현재/집계 점수를 null 처리하고 해당 관측을 집계에서 제외합니다.
기존 `orientation_state`의 분류는 유지하며, 이 추가 상태는 런타임·웹캠 전용입니다.
기존 아래 보기 기준 15도에 도달하면 `looking_down_uncertain`, 그 이상이 연속
`gaussian_down_confirm_seconds`(실험 기본값 0.3초) 유지되면 `looking_down_confirmed`입니다.
이는 머리의 아래 방향 확인일 뿐 필기·참여·미참여 확인이 아닙니다. 확인 시간은 실제 시각으로
계산하며 미검출·관측 공백·추적 변경·재보정 시 다시 시작합니다.
원래 below-looking 히스테리시스도 유지하므로, 설정 변경 시 아래 보기 해제 기준과 함께 검토해야 합니다.

전이는 처음부터 제외하므로 이후 아래 보기로 확인돼도 과거 발행 이벤트를 소급 수정하지 않습니다.
아래 보기로 이어지지 않은 전이 역시 불확실 관측으로 남고 0점이나 과거 점수로 대체하지 않습니다.
작은 양의 Pitch 10도 이하는 계속 Gaussian으로 계산합니다. 따라서 이 범위의 감소까지 제거하는
정책은 아닙니다. 정면 복귀 첫 유효 관측부터 현재 점수를 재개하며 집계는 기존 70% 기준을 따릅니다.
10도/0.3초는 논문 원식의 값이나 검증된 최적값이 아닌 프로젝트 실험값입니다.
설정은 `ModelConfig.gaussian(...)`에서 조정합니다.
모델/config 버전은 `angle-time-0.2`/`gaussian-angle-time-0.2`, 발행 확장 버전은
`angle-time-window-2`로 구분합니다. JSON 구조·model_output.value 의미는 유지하고 모델 전용
확장에 전이 설정만 기록합니다. 진단 스냅샷과 downward_status는 JSON으로 전달하지 않습니다.

웹캠 D 디버그는 보정 기준 P/Y, 추적 키와 변경 여부를 추가로 표시합니다.
점수 감소 시 직전/현재 관측의 원본·스무딩·상대각, 실제 사용 입력, 축별 항, 점수,
보정 기준과 추적 키를 메모리 복사본으로 보관합니다. 최근 8초(최대 100건)의 가장 큰 감소를
`HISTORICAL DROP`으로 표시하고 미검출/전이 중에도 유지합니다. 화면 시각은 발생 시각입니다.
모든 양의 점수 감소를 후보로 보관하므로 별도 급락 감지 임계값이나 행동 판정은 없습니다.
C 재보정 시 기록을 지우며, 파일·원본 미디어·JSON에는 저장하지 않습니다.

### 독립 웹캠의 화면 이탈 후 복귀

`webcam_demo.py`는 기존 `HeadCalibration`을 상속한 `WebcamHeadCalibration`을 해당 실행기에만 주입합니다. 완료된 정면 보정은 얼굴 미검출 동안 유지하며, 미검출 구간의 현재 점수는 `null`입니다. 얼굴이 다시 검출되고 유효한 상대각이 전달되면 첫 관측부터 현재 방향 점수를 계산합니다. 최근 10초 집계식과 품질 기준은 그대로입니다.

단일 얼굴의 일시적인 각도 계산 실패·품질 저하도 보정 기준은 유지하고 현재 상대각과 점수만 비웁니다. 다중 얼굴 또는 손상된 보정 기준은 재보정 대상으로 표시합니다. 보정 수집 중 미검출은 기존처럼 수집을 다시 시작합니다. 일반 화면에서도 재보정/관측 실패 사유를 표시합니다. 기본 영상에는 얼굴 랜드마크·경계 상자와 검출 상태가 표시되고, 미검출 시 과거 위치를 지운 뒤 복귀 시 자동 재개합니다. `V`는 시각화 전환, `D`는 상세 수치 전환입니다. 사용자가 바뀌거나 카메라 위치를 변경한 경우 자동으로 식별할 수 없으므로 `C`로 재보정해야 합니다. 이 정책은 팀원 영상 모듈과 프런트에는 적용하지 않습니다.

복귀 회귀 검증: `video_recognition/.venv/Scripts/python.exe -B -m unittest engagement_model.tests.test_webcam_recovery -v`. 실제 `VisionPipeline`에 합성 검출 결과를 주입하는 테스트이며 실제 카메라 재검출 성능 검증을 대신하지 않습니다.

### 현재 방향 점수와 시간 집계 점수

`GaussianRuntime.latest`는 두 점수를 구분합니다.

| 런타임 값 | 의미 | 70% 집계 기준 |
|---|---|---|
| `current_direction_score` | 최신 유효 상대각의 Gaussian 점수. 첫 관측부터 갱신 | 적용하지 않음 |
| `score` | 기존 최근 10초 시간 가중평균. 기존 `status`/`reason_codes`도 집계 상태를 설명 | 유지 |

현재 방향 점수는 정면→옆 보기→정면에 다음 유효 관측부터 반응합니다. 아래 보기·미검출·
보정 실패·입력 오류·초기화 상태에서는 null이며 과거 값으로 채우지 않습니다.
단, 영상 모듈의 스무딩/샘플링 이전 시점까지 즉시 반응한다는 뜻은 아닙니다.
아래 보기 후 복귀하면 현재 방향 점수는 바로 재개하지만, 집계 점수는 기존 정책에 따라
약 7초 보류될 수 있습니다. 이때 `status=deferred`여도 현재 방향 점수는 유효할 수 있습니다.

`current_direction_score`는 실행 메모리와 독립 테스트 화면 전용 선택 값입니다.
JSON 이벤트에는 넣지 않습니다. 기존 `model_output.value`는 계속 구간 집계이며
`WindowPublisher`는 현재 방향 점수 필드를 읽거나 저장하지 않습니다. 향후 영구 저장이
필요하면 모델 확장 영역의 선택 필드·의미·버전을 계약 담당자와 별도로 합의해야 합니다.

독립 웹캠 기본 화면은 영상·현재 방향 점수·10초 점수·상대 P/Y·sigma·행동/보정 상태를 표시합니다.
`D` 또는 `--debug`에서 10초 집계·Pitch/Yaw·사유 코드·sigma·표본 간격·다른 모델 비교를
확인합니다. 기본 얼굴 랜드마크/검출 표시는 `V`로 전환하며 상세 좌표는 디버그 모드에서 확인합니다.

`D` 디버그의 Gaussian 진단에는 원본·스무딩·상대 P/Y와 실제 사용한 `USED P/Y`,
보정 상태, sigma, 현재/10초 점수, 동일 입력의 sigmaYaw 20/30/40 예상 점수가 표시됩니다.
실제 사용값은 선택한 각도 모드의 입력이며 후보 비교는 설정이나 점수를 변경하지 않습니다.
`Exponent terms`는 `(P/sigmaP)^2`, `(Y/sigmaY)^2`이고, share는 그 합에 대한 비율입니다.
이는 점수 감쇠의 수학적 기여이며 실제 행동 원인을 확정하지 않습니다.
`Delta`는 연속 유효 관측의 최단 각도 변화와 현재 점수 변화입니다.
`Largest drop in last 5s`는 최근 최대 100개 감소 관측 중 5초 이내 최대 하락과 발생 시각,
축별 항 증가량을 표시합니다. driver는 점수 하락 때 더 크게 증가한 항의 축입니다.
미검출·아래 보기·하향 전이·추적 변경·관측 공백·C 재보정 시 변화량 비교를 끊습니다.
과거 급락 스냅샷은 위의 8초 유지 정책으로 별도 표시합니다.
진단은 디버그를 꺼도 갱신하지만 화면 표시는 디버그에서만 하며 파일/JSON에 저장하지 않습니다.

실제 확인 순서: C 정면 보정 → D → 정면 유지 → 작은 좌우 회전 → 정면 복귀 →
화면 이탈·복귀. 급락 시 `USED P/Y`, 원본/스무딩 값, 축별 항과 driver를 비교합니다.
작은 회전에 USED yaw가 약 70도이거나 pitch도 크게 변하는지 확인하고,
동일 입력 후보 점수로 sigma 영향과 입력 급변을 구분합니다. 실제 회전량과의 일치나
특징 추출 오류 여부는 이 수치만으로 확정할 수 없습니다.

```powershell
video_recognition/.venv/Scripts/python.exe -B -m engagement_model.webcam_demo
video_recognition/.venv/Scripts/python.exe -B -m engagement_model.webcam_demo --debug
```

`gaussian.py`의 `GaussianRuntime`을 별도로 추가했습니다. 기존 `EngagementRuntime()`과
Huang 온라인 0.2 계산·상태는 유지합니다. `ComparisonRuntime(include_gaussian=True)`로
동일한 특징에서 세 모델을 실행하며 입력 추출을 중복하지 않습니다.

Li, B.; Liu, P. (2024), *Online Learning State Evaluation Method Based on Face Detection
and Head Pose Estimation*, Sensors 24(5), 1365,
[DOI 10.3390/s24051365](https://doi.org/10.3390/s24051365), §3.3 식 (8)~(10)을 참고합니다.
논문 Gaussian은 화면 중심과 머리 방향 투영점의 좌표 차이, 유효 시야의 폭/높이를 사용하고
sigma를 각각 시야 폭/높이의 0.2배로 둡니다. 현재 입력에는 이 기하 정보가 없습니다.
따라서 화면 투영 좌표를 코 위치로 대체하거나 논문의 0.2를 각도에 그대로 적용하지 않습니다.

프로젝트 **각도 공간 변형**의 relative 비교 모드는 스무딩·정면 보정 후 yaw 압축 전 상대각,
기본 softened 모드는 위의 중립 완화 후 각도를 사용합니다.

```text
S_angle = 100 * exp(-0.5 * ((relative_pitch / sigma_pitch)^2
                         + (relative_yaw   / sigma_yaw)^2))
```

`ModelConfig.gaussian()`의 sigma 초기값은 pitch=15도, yaw=20도입니다. 논문이 제시한
각도나 검증된 최적값이 아니라 명시적인 실험 후보입니다. 원점에서 100점이며 각도 편차가
커지면 감소합니다. 거리·얼굴 면적 임계값·60점 경고 규칙은 채택하지 않습니다.
`gaussian_angle_score()`는 범위와 유한값을 확인하며 큰 편차에서도 overflow 없이 계산합니다.

논문의 최근 10초 기록 순서 평균은 `li_liu_rank_average()`에 별도로 보존합니다.

```text
S_rank = sum(k * S_k, k=1..K) / sum(k, k=1..K)  # 오래된 순서, 식 (10)과 동일
```

영상 파이프라인의 10Hz는 목표 주기이며 실제 시각 간격이 같다고 보장하지 않습니다.
따라서 실행 모델은 동일한 선형 최근성 원리를 **실제 시간에 적분하는 변형**을 사용합니다.

```text
W = 10초 (기본 설정)
a = 현재 구간 끝 - W
w(t) = (t-a)/W
S_time = sum(S_angle(segment) * integral_segment(w(t) dt))
         / sum(integral_segment(w(t) dt))
```

적분은 유효 관측 구간에서만 수행합니다. 값이 없는 구간을 0점으로 바꾸지 않습니다.
이 변형은 균일 표본에서도 원식의 정수 순서 가중치와 정확히 같은 식은 아닙니다.
`sampling_diagnostics()`는 최근 관측 간격의 최소/최대와 정확히 동일한 간격인지 보고합니다.
100ms 균일 표본과 50/150ms 불규칙 표본의 같은 시간별 행동은 같은 점수로 검증합니다.

## Huang 기반 선택 모델과 기존 모델 비교

기본 `ModelConfig()`와 프런트는 기존 `legacy` 점수식을 유지합니다. 개선 모델은
`EngagementRuntime(ModelConfig.huang())`로 선택합니다. 입력 `FeatureWindow`와 기존
`score`/`status`/`orientation_state`/`reason_codes` 출력은 유지하며 모델 버전은
`huang-online-0.2`로 구분합니다. 프런트에 모델 선택 UI를 추가하지 않았습니다.
기존 프런트의 `LiveSession`은 계속 기본 모델을 생성합니다.

### 원식과 온라인 변형

출처: Huang, Zhuo, Gao (2024), *How attentive is a student in class? A concentration
evaluation method based on head Euler angle*,
[DOI: 10.1016/j.heliyon.2024.e37365](https://doi.org/10.1016/j.heliyon.2024.e37365),
[원문 Method §3.1~3.3](https://pmc.ncbi.nlm.nih.gov/articles/PMC11417239/).

원문의 `SP_i`는 큰 구간 Pitch 시퀀스, `S`는 전체 영상 시퀀스, `p_ij`는 작은 구간의
평균 Pitch이며, 위쪽이 양수입니다. `scoring.py`의 순수 함수는 다음 식을 구현합니다.

```text
(1) q_i = median(SP_i), if |Δ(SP_i)| >= θ; otherwise median(S)
(2) a_ij = |(p_ij - q_i) / (max(SP_i) - q_i)|, if p_ij >= q_i
           |(p_ij - q_i) / (min(SP_i) - q_i)|, otherwise
(3) P_ij = 1 / (1 + exp(-a_ij * (p_ij - q_i)))
(4) β = |yaw| - cs, if x >= W/2; otherwise |yaw| + cs
(5) cs = atan(|x - W/2| / y)
(6) Y = 1 - β/O                       # 백분율을 0~1 비율로 표현
(7) C = 1 - sqrt((Y-1)^2 + (P-1)^2) / sqrt(2)
```

`huang_head_up()`는 식 (1)~(3), `huang_front_facing()`은 식 (4)~(6),
`huang_concentration()`은 식 (7)입니다. Δ는 max-min 진폭으로 해석합니다.
`huang_head_up()`에 원식의 전체 중앙값은 `reference_pitch`로 명시해서 전달합니다.
원식 검증 함수의 기본 동작은 분모 0에서 `None` 보류이며 임의 epsilon을 넣지 않습니다.
온라인 호출은 `neutral_on_degenerate=True`로 p=q인 퇴화 구간만 P=0.5로 확장합니다.
이는 sigmoid 입력 차이 0에 대응하는 **프로젝트 중립 정책**이며 논문의 명시된 예외식은 아닙니다.
분모가 0이어도 p≠q이면 계속 보류합니다. NaN/무한대 입력은 거부하고 표현할 수 없는
중간 계산값은 보류합니다. P/Y 가중 평균의 부동소수점 경계 오차도 0~1로 제한합니다.
`huang_front_facing()`은 원식의 범위를 조용히 고치지 않습니다. 공간 보정 결과가
0~1 밖이면 결합 함수가 거부하므로 호출자가 좌표와 원식의 적용 조건을 점검해야 합니다.

온라인 경로 `huang_window_score()`에는 아래의 **프로젝트 변형**이 적용됩니다.

- 기존 보정된 상대 Pitch를 부호 반전하고, yaw 압축 전 `source_angles`를 사용합니다.
- 전체 영상 중앙값을 미래에 알 수 없으므로 작은 진폭 구간의 기준은 보정 정면 **0도**입니다.
  과거 전체 중앙값을 근사하는 모델이나 논문 전체 영상 재현 모델은 아닙니다.
- 교실 공간좌표가 없는 수업 타일에는 원문 식 (4)~(5)를 적용하지 않습니다.
  `Y_local = clip(1 - abs(relative_yaw)/O, 0, 1)`로 대체합니다.
- 논문 실험값 θ=5도, O=90도를 사용합니다. 기본 큰 구간 30초·작은 구간 3초는
  논문이 제시한 20~30초·약 3초 범위에서 선택한 프로젝트 설정입니다.
- 큰 구간은 현재까지의 이동 구간입니다. 작은 구간의 평균 Pitch/Yaw 지표와
  최종 P/Y는 유효 관측 시간으로 가중하고, 큰 구간 중앙값은 유효 표본으로 구합니다.
  작은 구간별 sigmoid 결과를 각 구간에 대응시킨 후 P/Y를 함께 집계합니다.
- 끝의 미완료 작은 구간, 관측 공백, 아래 보기, 퇴화한 Pitch 구간은 점수화 시간에서 제외합니다.
  관측률·점수화 시간 비율 gate는 기존 70%, 관측 유지 상한은 0.3초를 재사용합니다.
- 최종 출력은 `100*C`입니다. 시점별 C의 평균이나 이미 계산된 이동 점수의 재평균이 아닙니다.

정확히 정지한 정면 0도는 온라인 모델에서 P=0.5, yaw=0일 때 약 64.6점입니다.
정면을 무조건 100점으로 올린 결과가 아니라 중립 P와 원래 거리식을 결합한 값입니다.
정면 범위의 작은 각도 차이만으로도 기존 점수와 크게 다른 결과가 나올 수 있습니다.
예를 들어 위쪽 상대 Pitch 2도가 일정하고 yaw=0이면 P=sigmoid(2), 약 91.6점입니다.

재하향·관측 공백·트랙 변경·보정 실패의 기존 보류/초기화 처리를 유지합니다.

손·필기구·교재 인식은 추가하지 않았습니다. 현재 상체 출력은 어깨 중심·가시성이며

원본 영상·음성·진단 로그·세션 JSON은 저장하지 않습니다. 종료 시 터미널에 프레임 기준
비교 요약을 출력하며 보정 전 프레임도 포함합니다. 정확도나 수업 전체 평균이 아닙니다.
독립 창의 영어 표기는 OpenCV 기본 폰트의 한글 표시 제한 때문이며 사유 코드를 함께 표시합니다.

```powershell
# 기존 데모 동작 유지
video_recognition/.venv/Scripts/python.exe -m video_recognition.webcam_test
# 개선 모델과 기존 모델의 계산·보류·호환성 검증 (카메라 불필요)
video_recognition/.venv/Scripts/python.exe -B -m unittest engagement_model.tests.test_huang -v
# 합성 입력에서 모델별 점수와 보류 비율 출력 (카메라·로그 생성 없음)
video_recognition/.venv/Scripts/python.exe -B -m engagement_model.tests.test_huang --compare
```

기존 웹캠 데모와 프런트 파일은 수정하지 않습니다. 기존 웹캠에는 새 모델 선택 옵션이 없으며,
계속 기존 모델을 사용합니다. Huang 전용 안내 문구와 비교 로그도 웹캠에 추가하지 않습니다.
모델 비교는 `engagement_model/tests/test_huang.py`에서 같은 합성 `FeatureWindow`를
두 런타임에 전달해 수행합니다. `ComparisonRuntime`은 각 모델의 시간 상태를 독립적으로 관리합니다.
영상 모델을 재구현하거나 테스트용 원본 미디어를 저장하지 않습니다.
서로 점수화한 구간이 다르므로 각 평균은 직접적인 정확도 비교가 아닙니다. 워밍업과 미검출도
보류 비율에 포함합니다. 사람 주석 없는 합성 입력 결과를 실제 참여도 정확도로 보고하지 않습니다.
합성 비교는 정면 준비 30초 후 각 행동을 30초 동안 100ms 간격으로 입력합니다.
정면은 상대 pitch=-2도, 옆 보기는 pitch=-2도/yaw=60도, 아래 보기는 pitch=20도입니다.
복귀 사례는 추가로 아래 보기 30초 후 정면을 입력합니다. 평균은 유효 점수가 있는
평가 프레임만 대상으로 하고 보류 비율은 평가 프레임 전체를 분모로 합니다.
완전 정지 pitch=0도 사례는 준비부터 0도로 입력해 온라인 중립 처리를 별도로 확인합니다.
기존 개발자 패널은 출력 형식을 읽을 수 있으나 Huang 전용 규칙 설명은 제공하지 않습니다.

동일 합성 시나리오에서 온라인 0.1→0.2 비교 결과:

| 평가 상황 | 0.1 | 0.2 |
|---|---|---|
| 정지 Pitch 0도, 준비 구간 이후 | 보류율 100%, 점수 없음 | 보류율 0%, 평균 64.6점 |
| 아래 보기 후 복귀, 평가 30초 | 보류율 70% | 보류율 10%, 처음 3초 후 재개 |
| 아래 보기 / 얼굴 미검출 | 각각 보류율 100% | 각각 보류율 100% 유지 |
| 기존 legacy 모델 | 변경 없음 | 변경 없음 |

0.2 검증은 모델 테스트 59개(기존 모델 회귀·순수 원식·0도/미세 흔들림·복귀 재보류·
구간 저장 보존·웹캠 실행기 모의 오류 검사 포함)로 확인합니다. 이 표는 합성 입력의
동작 비교이며 실제 영상 정확도나 실제 필기 인식 성능이 아닙니다.

`WindowPublisher`에는 동일 런타임을 주입할 수 있으며 해당 버전으로 계약 이벤트를 발행합니다.
최소 각도는 이동 구간 동안 메모리에만 유지하며 `huang_observation`이나 임시 트랙 키를
최종 세션 JSON에 넣지 않습니다. 모델 선택을 프런트에 추가하려면 `LiveSession`이 생성하는
런타임과 세션/상태 provenance를 함께 바꿔야 하므로 이번 변경 범위에서는 제외했습니다.

검증 명령:

```powershell
video_recognition/.venv/Scripts/python.exe -B -m unittest discover -s engagement_model/tests -v
video_recognition/.venv/Scripts/python.exe -B -m unittest discover -s frontend/tests -v
```

아래의 기존 구현 설명과 테스트 개수는 legacy 개발 이력입니다. 최신 검증 범위에는
`tests/test_huang.py`의 원식 손계산·하향 보류·복귀·결측·구간/JSON 회귀 검사가 추가됩니다.

## 1. 개요

개인별 정면 기준에 대한 머리 방향 차이와 자세 유지 시간을 이용해 0~100점의 행동 점수를 계산하는 실험용 모듈입니다.

**점수는 실제 집중도나 이해도의 직접 측정값이 아닙니다. 모든 각도·시간·점수 계수는 검증 전 실험 후보입니다.**

[video_recognition](../../video_recognition/README.md)이 얼굴 검출과 정면 보정을 담당하고, 이 모듈은 그 결과를 검증하고 점수화합니다. 웹캠 데모와 개발자 미리보기는 시점별 결과를 표시합니다. 라이브 세션에서는 별도 집계기가 구간 이벤트를 통합부에 전달합니다.

- 입력: VisionPipeline의 시점별 `FeatureWindow` 사전
- 내부 자료: `Observation`과 정면 기준 상대 각도 `HeadAngles`
- 출력: 데모 실행기의 0~100 실험 행동 점수, 자세 상태, 지속 시간, 판단 보류 사유
- EAR, 깜빡임, blendshape, 상체 위치는 현재 점수 계산에 사용하지 않습니다.

## 2. 전체 처리 흐름

```text
video_recognition: FeatureWindow 생성
  ↓ 호출자가 parse_feature_window()에 전달
input_adapter.py: 형식·얼굴 개수·보정·품질·상대 각도 검사
  ↓ Observation 반환
runtime.py: FeatureWindow 콜백 수신, 시각 간격과 자세 지속 시간 관리
  ↓
scoring.py: classify_orientation()으로 자세 후보 분류
  ↓ 정면 / 이탈 / 아래 보기 / 불명확 / 관측 불가
scoring.py: behavior_score()로 점수 계산
  └─ 이탈 상태에서는 orientation_severity()로 각도 강도 계산
  ↓ 데모 화면에 모델 상태·점수·보류 사유 표시
```

`runtime.py`가 받은 특징의 세션 시각을 이용해 자세 유지 시간을 관리합니다. 이 상태는 메모리에만 있으며 얼굴 추적이 끊기거나 0.3초보다 긴 관측 공백이 생기면 초기화합니다. 라이브 세션에서는 `window_publisher.py`가 결과를 시간 구간으로 집계합니다.

## 3. 파일별 역할

| 파일 | 주요 구성 | 구현 내용 |
|---|---|---|
| [config.py](../config.py) | `ModelConfig`, `__post_init__()` | 실험 설정 보관과 값 검증 |
| [input_adapter.py](../input_adapter.py) | `HeadAngles`, `Observation`, `parse_feature_window()` | 기존 영상 출력 검증·변환 |
| [scoring.py](../scoring.py) | `classify_orientation()`, `orientation_severity()`, `behavior_score()` | 자세 후보·이탈 강도·행동 점수 계산 |
| [runtime.py](../runtime.py) | `EngagementRuntime` | 단일 얼굴 데모의 시간 상태 관리와 모델 콜백 실행 |
| [window_publisher.py](../window_publisher.py) | `WindowPublisher` | 실험 구간 집계 및 통합부 이벤트 발행 |
| [tests/test_model.py](../tests/test_model.py) | `ConfigTests`, `AdapterTests`, `ScoringTests` | 설정·입력 어댑터·점수 규칙 테스트 |
| `__init__.py`, `tests/__init__.py` | 패키지 설명 | 별도 실행 로직 없음 |

### config.py

`ModelConfig`는 생성 후 값을 바꾸지 못하는 자료 클래스입니다. 다른 설정으로 실험하려면 새 객체를 만듭니다. 각도 단위는 도, 시간 설정 단위는 초입니다.

- 기본 버전: 설정 `experimental-0.4`, 입력 특징 `experimental-0.8`
- 정면: yaw ±15도, pitch ±10도
- 좌우 이탈: 30도부터, 60도에서 강도 상한
- 위쪽 이탈: 20도부터, 40도에서 강도 상한
- 아래 보기: 스무딩 상대 pitch +15도 이상
- 아래 보기: 5초 유예 후 10초 동안 시작 점수에서 최대 20점 감점, pitch가 +10도 이하가 되면 아래 보기 상태 해제
- 좌우 민감도 보완: 2도 중립 데드밴드, 15도까지 0.75배 압축, 그 이상은 큰 회전 보존을 위해 오프셋만 적용
- 이탈 유예 3초, 시간 감점 상한 10초, 정면 보너스 상한 5초
- 정면 기본 90점·보너스 10점, 이탈 기본 70점·각도 감점 30점·시간 감점 40점

`__post_init__()`는 음수·무한대·참/거짓 값, 잘못된 각도 순서, 0으로 나누게 되는 설정 등을 거부합니다.

최대 관측 유지 0.3초는 자세 유지 상태와 구간 집계의 결측 처리 기준입니다. 10초 집계, 2초 출력, 시간 기준 최소 관측률과 점수화 비율 0.7을 라이브 집계에 적용합니다. 2초 복귀 확인은 아직 설정만 있습니다.

### input_adapter.py

- `HeadAngles`: 상대 `pitch`, `yaw`, `roll` 저장
- `Observation`: 세션 ID, 시각, 특징 버전, 각도, 사유 코드, 임시 추적 키 저장
- `Observation.observable`: 각도가 있으면 `True`, 없으면 `False`
- `parse_feature_window(data, config=None)`: 원본 입력을 수정하지 않고 관측 객체 반환

현재 입력 조건은 다음과 같습니다.

| 입력 | 검사·처리 |
|---|---|
| `session_id` | UUID 문자열 검사 |
| `start_ms`, `end_ms` | 0 이상의 정수, 두 값이 같은 시점 입력만 지원 |
| `feature_version` | 설정의 특징 버전과 일치해야 함 |
| `features.faces` | 단일 얼굴만 지원 |
| `head_calibration_status` | `ready`여야 각도 사용 |
| 얼굴별 `quality.status` | `valid` 또는 `partial` 허용. 이 모델이 쓰는 상대 머리 각도가 유효해야 함 |
| `head_angles_relative_degrees` | 스무딩 각도로 계산한 상대각. yaw는 모델 설정의 작은 각도 보정을 거침 |

잘못된 버전·시간·자료 구조는 `ValueError`로 알립니다. 미검출·복수 얼굴·보정 미완료·품질 부족·각도 결측은 `angles=None`과 사유 코드를 반환합니다. 사유에는 `face_not_found`, `multiple_faces_unsupported`, `baseline_unavailable`, `landmark_low_quality`, `relative_angles_unavailable` 등이 있습니다.

모델은 머리 각도만 사용하므로 눈 개방도나 표정 blendshape가 빠져 얼굴 품질이 `partial`이어도 상대 머리 각도가 유효하면 사용할 수 있습니다. 얼굴 품질이 `not_observable`이거나 상대 각도가 없으면 사용하지 않습니다. 최상위가 `not_observable`이어도 제외합니다. 임시 추적 키는 메모리 상태 연결에만 쓰며 학생 식별·추적 기능은 아닙니다.

### scoring.py

- `classify_orientation()`: 한 시점의 자세 후보 분류. 지속적인 비참여 판정은 아님
- `orientation_severity()`: 좌우·위쪽 이탈 강도를 0~1로 반환. 아래 보기·결측은 `None`
- `behavior_score()`: 관측과 전달받은 유지 시간으로 행동 점수 반환. 함수 자체는 무상태이며 데모에서는 `EngagementRuntime`이 시간 인자를 계산
- 내부 함수 `_number()`, `_validate_angles()`, `_clip()`: 숫자·각도 검사와 범위 제한

세 함수는 같은 `ModelConfig`를 사용할 수 있습니다. `EngagementRuntime`은 어댑터가 만든 관측만 점수 함수에 전달합니다.

## 4. 점수 계산 알고리즘

### 상대 각도와 자세 후보

영상 모듈이 계산한 개인별 정면 대비 상대 각도를 사용합니다. `experimental-0.8`부터 정면 기준 수집과 모델 입력 모두 프레임 간 스무딩된 각도를 사용합니다. 원본 기반 상대 각도는 `head_angles_relative_raw_degrees`로 보존합니다. 모델 입력 어댑터는 작은 좌우 편차를 줄이기 위해 기본 2도 이하는 0도로 두고, 2~15도는 0.75배로 완화합니다. 15도를 넘는 값은 큰 회전을 거의 그대로 유지하면서 이 구간에서 생긴 오프셋만 뺍니다. 변환 전 값은 `Observation.source_angles`와 개발자 화면의 source yaw로 비교할 수 있습니다. 이 민감도 보정은 점수 모델 입력에만 적용하고 VisionPipeline 특징 원본은 변경하지 않습니다. yaw는 좌우 회전, pitch는 위아래 회전입니다. 현재 환경에서 pitch 양수는 아래쪽입니다. roll은 좌우 기울기이며 현재 점수에는 사용하지 않고 값의 유효성만 검사합니다.

기본 설정에서 아래 순서로 분류합니다.

| 순서 | 조건 | 상태 |
|---|---|---|
| 1 | 각도 없음 | `not_observable` |
| 2 | pitch ≥ +15도, 또는 직전 상태가 `looking_down`이고 pitch > +10도 | `looking_down` |
| 3 | yaw 절댓값 ≤ 15도, pitch 절댓값 ≤ 10도 | `front` |
| 4 | yaw 절댓값 ≥ 30도 또는 pitch ≤ −20도 | `away` |
| 5 | 나머지 | `ambiguous` |

아래 보기를 먼저 분류하므로 아래+옆 보기 역시 아래 보기의 유예·완만 감쇠 규칙을 적용합니다. pitch가 +10도 이하로 회복되면 아래 보기 상태를 해제합니다. 필기나 자료 확인을 직접 인식하지는 않습니다.

### 계산식

`clip(x)`는 0~1, `clip100(x)`는 0~100으로 값을 제한합니다. 아래는 기본 설정을 대입한 식입니다.

정면 유지 점수:

```text
S_front = 90 + 10 × clip(front_seconds / 5)
```

방향 이탈 강도와 지속 시간 비율:

```text
A_yaw = clip((abs(yaw) − 30) / 30)
A_up  = clip((−pitch − 20) / 20)
A     = max(A_yaw, A_up)
D     = clip((away_seconds − 3) / 7)
```

이탈 시간이 3초를 초과했을 때:

```text
S_away = clip100(70 − 30 × A − 40 × D)
```

3초 이내의 이탈은 `previous_stable_score`를 그대로 반환합니다. 이전 안정 점수가 없으면 `None`입니다. 정면 복귀 확인과 시간 자동 누적은 아직 구현하지 않았습니다.

| 입력 예시 | 결과 |
|---|---|
| 정면 범위, 정면 유지 2.5초 | 95점 |
| yaw 45도·pitch 0도, 이탈 6.5초 | A=0.5, D=0.5 → 35점 |
| yaw 60도, 이탈 3초, 이전 안정 점수 95점 | 95점 유지 |
| pitch +15도, 아래 보기 5초 유지, 시작 점수 90점 | 90점 유지 |
| 같은 상태를 15초 유지 | 70점 — 시작 점수 90점에서 5초 유예 후 10초에 걸쳐 최대 20점 감점 |

### None과 0점의 구분

`behavior_score()`는 불명확·관측 불가와 이전 안정 점수가 없는 초기 아래 보기에 `None`을 반환합니다. 아래 보기는 안정 점수가 있으면 5초까지 해당 점수를 유지하고, 이후 설정된 완만한 감점을 적용합니다. 라이브 구간 집계에서도 결측은 0점으로 대체하지 않습니다.

0점은 유효한 입력으로 계산된 낮은 행동 점수입니다. 미검출이나 보정 실패를 0점으로 바꾸지 않습니다. 아래 보기 점수와 관측 불가는 자세 분류 결과 및 관측 사유를 함께 확인해 구분해야 합니다.

좌우/위쪽 이탈은 3초 유예를 사용하고 아래 보기에는 별도의 5초 유예와 10초 완만 감쇠를 사용합니다. 아래 보기 시작은 +15도, 해제는 +10도 기준으로 분리해 경계 근처의 흔들림에 타이머가 자주 초기화되지 않게 합니다. 이 정책은 필기·자료 확인과 장시간 이탈을 구분하지 못하므로 점수 계수와 유예시간은 후속 실험 대상입니다.

### 점수 보류 중 화면 표시

실시간 데모에서 현재 프레임의 점수 산출이 보류되면 실제 `score`는 계속 `null`로 둡니다. 화면 흐름을 읽기 쉽도록 마지막 유효 점수를 최대 2초 동안 별도 `display_score`에 보관하며, 이 값은 출력용 캐시입니다.

- 유효한 새 점수: `display_state="current"`, `display_score`에 현재값, `display_age_ms=0`
- 점수 보류 후 2초 이내: `score=null`, `display_state="held"`, 이전값과 경과 시간 표시
- 2초 초과: `score=null`, `display_state="expired"`, `display_score=null`
- 아직 유효 점수가 없음: `display_state="unavailable"`

개발자 패널은 보류값에 `HELD`와 현재 점수 산출 불가 상태를 함께 표시하고, 웹캠 데모 터미널은 상태가 바뀔 때 표시값과 경과 시간을 기록합니다. 보류된 값은 점수식의 이전 안정 점수, 세션 이벤트, 타임라인 또는 저장 결과에 입력되지 않습니다. 즉 흐름을 화면에서 잠깐 이어 보여주는 기능이며, 현재 시점의 점수로 해석하거나 기록하면 안 됩니다.

## 5. 단일 얼굴 데모 실행

저장소 루트에서 실행합니다. MediaPipe 영상 의존성을 설치한 Python 환경이 필요합니다.

```powershell

```

웹캠 창에서 한 사람만 보이게 하고 결과 창에서 `C`를 눌러 정면을 보고 움직이지 않은 채 3초 기준을 수집합니다. 결과 패널에는 보정 샘플 수·경과 시간·진행률·마지막 거부 사유, 모델 ID·버전, 실제 적용 임계값, 상대 pitch/yaw/roll, 자세 분류, 자세별 유지 시간, 점수 또는 보류 사유가 표시됩니다. `video_recognition/demo_logs/`에 실행별 JSONL 파일이 생성되며, 실행 설정과 매 분석 프레임의 원본·스무딩·보정 상대각, 품질, 보정 상태, 현재 점수 및 화면용 보류 점수를 기록합니다. 영상 자체는 로그에 저장하지 않습니다. 터미널도 상태가 바뀔 때 진단 한 줄을 출력합니다. 현재 시험 기준은 pitch 정면 ±10도, 아래 보기 +15도, 위쪽 이탈 −20도입니다. 아래 보기 점수는 유효한 이전 점수가 있을 때 5초간 유지한 뒤 10초 동안 최대 20점 낮아집니다. 값과 정책은 검증 전 비교 실험용입니다.

`V`, `M`, `[`/`]`, `Q`는 영상 개발자 미리보기와 같은 오버레이·메시·얼굴 페이지·종료 조작입니다. 보정 단계는 한 얼굴이 검출되고 머리 각도가 계산되는지, 10개 이상 샘플과 3초가 모이는지, 자세가 안정적인지 확인합니다. 자동으로 정면을 판별하는 절차는 아니므로 사용자가 실제 정면을 바라봐야 합니다. 점수는 화면 확인용이며 세션 파일이나 `engagement_window` 이벤트로 저장되지 않습니다. 이 데모는 얼굴 하나만 지원합니다.

### 라이브 구간 이벤트

기본 10초 이동 구간을 2초마다 출력합니다. 첫 정기 결과는 수업 시작 10초 후이며, 종료할 때 마지막 구간도 발행합니다. 10초 전에 끝나면 실제 경과 시간의 부분 구간입니다. 각 시점의 점수는 다음 시점 또는 최대 0.3초까지만 유지해 시간 가중 평균을 계산합니다. 0.3초를 넘는 관측 공백은 결측입니다. 관측 가능 시간과 점수화 가능 시간이 각각 구간의 70% 미만이면 점수는 `null`이고 사유를 기록합니다.

`model_output.value`는 0~100 실험 점수입니다. `model_extensions.head-orientation-rules`의 `observable_duration_ms`, `scoreable_duration_ms`, `window_duration_ms`, `observable_time_ratio`, `scoreable_time_ratio`는 **시간 기준**이며 참가자 수나 참가율이 아닙니다. 공통 `observation`의 인원 분모와 비율은 미정이므로 `null`로 남깁니다. 구간에는 원본 프레임·얼굴 좌표·개인 ID를 넣지 않습니다. 겹치는 이동 구간을 단순 평균해 수업 전체 점수로 표시하지 않습니다. 실제 성능과 70% 기준은 아직 검증 전입니다.

정답 점수가 없는 동안 MAE를 실제 성능으로 보고하지 않습니다. 먼저 독립적으로 작성한 행동·참여 상태 레이블과 예외 상황 평가를 사용하고, 점수 평가 데이터가 준비되면 MAE를 추가합니다.
