# 프런트 다인 재식별·Gaussian 통합 설계

## 요청과 현재 상태

사용자는 기존 기능의 단순 연결 대신, 재식별된 사람마다 Gaussian 점수를 계산하는 확장을 선택했다.
현재 프런트 LiveSession은 Legacy 단일 얼굴 런타임과 WindowPublisher를 사용한다.
재식별과 Gaussian은 독립 데모에 있으며, 최신 main의 성능 진단은 유지한다.
이전 작업은 이미 main에 병합됐고 현재 작업 브랜치는 main의 01bb61d까지 반영했다.

## 대안과 선택

1. Gaussian 단일 얼굴 점수와 다인 ID 표시만 연결: 작지만 다인 점수 요구를 만족하지 않는다.
2. ID별 Gaussian 런타임·보정을 만들고 그룹 집계만 저장: 사용자가 선택한 확장 방향이다.
3. 개인별 장기 이력까지 저장: 요청 범위를 넘고 기존 개인정보 원칙과 계약을 바꿔야 하므로 포함하지 않는다.

## 사용자 흐름

- 준비 화면에서 Gaussian 실험 점수와 세션 내 얼굴 재식별을 선택하고 수업을 시작한다.
- 영상·점수·재식별을 함께 선택하면 다인 Gaussian 경로로 실행한다.
  재식별을 끄면 단일 얼굴 Gaussian으로 실행하며 다인 점수 제한을 안내한다.
- 재식별 ID가 확정되기 전에는 임시 얼굴 위치를 개인으로 가정하지 않고 `ID 확인 중`으로 둔다.
- 확정된 ID별로 정면 기준을 약 3초 자동 수집한다. 처음 수집한 자세가 정면인지는 자동 검증하지 못한다.
  교수자에게 모두 정면을 유지하도록 안내하고 기존 재보정 버튼은 현재 관측된 사람의 보정을 다시 시작한다.
- 라이브 화면에 해당 세션의 임시 ID, 현재 관측 상태, 현재 Gaussian 점수와 최근 구간 점수를 표시한다.
- 개발자 프리뷰에 같은 분석 프레임의 얼굴과 임시 ID를 표시한다.
- 현재 얼굴이 관측되지 않으면 현재 점수는 null이다. 같은 ID가 재등장하면 해당 ID의 계산 상태로 연결한다.
  재등장 전후 시간은 연속 유효 관측으로 취급하지 않는다. 과거 점수를 현재 점수처럼 보여주지 않는다.
- 수업 종료 시 ID·임베딩·보정·개인별 계산 상태를 지운다. 재열기 화면에는 개인별 표를 복원하지 않는다.

## 구현 경계와 시간

- `face_reidentification.py`의 추론/ID 연결과 렌더링을 분리한다. 기존 annotate API는 호환 유지한다.
  프리뷰가 꺼져도 재식별은 실행하고 프리뷰 렌더링은 추론을 중복 호출하지 않는다.
- LiveSession에서 후처리된 얼굴의 임시 트랙과 같은 프레임의 얼굴 경계로 재식별을 실행한 뒤
  `engagement_model/multi_face.py`에 ID별 단일 얼굴 관측을 메모리로 전달한다.
  ID를 FeatureWindow나 이벤트 payload에 추가하지 않는다.
- ID별 HeadCalibration/GaussianRuntime을 두고, 원본 특징을 변경하지 않은 단일 얼굴 복사본만 전달한다.
  같은 ID의 추적이 끊기면 시간 상태를 끊고 복귀 품질을 확인한다. 이전 보정을 계속 쓸 수 있는지와
  머리 이동 상태는 별개로 관리한다. 카메라 이동이나 잘못된 정면 기준은 재보정이 필요하다.
- 공통 상대 시각을 사용한다. ID 간 점수·각도·보정과 추적 상태를 섞지 않는다.
- 재식별 모델 로딩/추론 실패는 UI에 표시하고 개인별 점수를 보류한다. 영상과 STT는 계속 실행한다.
  기존 재식별 모델의 세션 내 ID와 연결 유지 중 추론 중단 정책을 재사용한다.
- MobileGaze 시선 옵션은 이번 통합에 포함하지 않는다. 아직 정확도 검증 중인 별도 실험이다.

## 그룹 점수와 저장

개인별 현재/최근 점수 표는 메모리 전용이다. JSON에는 기존 engagement_window 이벤트로
이름·ID를 제외한 그룹 집계만 저장한다. 기존 UI와 강의 조교는 그 그룹 이벤트를 읽는다.

그룹 구간 점수는 각 ID의 같은 구간에서 유효한 Gaussian 관측을 먼저 계산하고,
유효 관측 사람·시간으로 가중 집계한다. 미검출·보정 중·재식별 미확정·아래 보기 보류는
0점으로 대체하지 않는다. 화면에서 관측되지 않은 전체 재학생 수나 참여율은 추정하지 않는다.
저장 provenance는 다인 Gaussian임을 명시하고, 집계 규칙과 분모를 문서화한다.
WindowPublisher는 다인 런타임의 집계 훅을 사용해 이미 평균된 점수를 재평균하지 않는다.
그룹 구간에 전혀 유효 관측이 없으면 model_output=null이다.
계약의 model_extensions에 집계 분모를 넣을 필요가 있으면 문서와 검사도 함께 갱신한다.

## 검증

두 사람이 동시에 나타남, 서로 다른 각도/보정 기준, 한 명 이탈·동일 ID 복귀,
ID 미확정·겹침·교차·추적 변경, 전원 미검출, 재보정, 모델 오류와 종료 자원 반환을 검사한다.
실제 이벤트 발행·저장·재열기에서 그룹 Gaussian provenance가 유지되고
ID·임베딩·얼굴 이미지·개인별 이력이 없는지 검사한다.
프런트 선택과 라이브 표, 기존 STT·조교·성능 진단의 회귀 검사를 수행한다.
Windows 실제 창 캡처와 다인 정확도는 실제 장치에서 실행한 경우에만 검증됐다고 보고한다.
커밋·푸시는 이번 요청에 포함하지 않는다.

구현 전 기준 검사: 현재 Mac에서 frontend/tests 30개 중 29개 통과, Windows 창 목록
선택 검사 1개 실패. 해당 검사는 list_windows만 모의하고 플랫폼 분기를 바꾸지 않아
Mac에서는 창 목록을 불러오지 않는 경로를 탄다. 기능 구현으로 새로 생긴 실패가 아니다.
