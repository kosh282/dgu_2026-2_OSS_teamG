# 코드베이스 검토 및 개선 결과

검토 기준: 2026-11-15 작업 시작 당시의 로컬 코드와 미커밋 변경. 기존 변경·미추적 실험 파일·수업 JSON은 보존했다. 새 의존성은 추가하지 않았다.

## 1. 구조와 현재 구현 수준

| 영역 | 역할과 연결 | 평가 |
|---|---|---|
| `frontend/app.py`, `dashboard_data.py` | Streamlit 준비·라이브·사후 검토, 메모·전사 수정, 파일 관리 | 화면은 이벤트 스냅샷을 읽고 변경은 통합부에 전달한다. 1초 주기 갱신과 매번 전체 기록 조회는 장시간 수업에서 추가 측정이 필요하다. |
| `frontend/live_session.py` | 세션 공통 시계, 영상·STT 감독 스레드, 모델 발행기, 15초 복구 저장 | 컴포넌트 실패를 분리하고 재시도한다. 네이티브 호출 중단과 다중 브라우저 세션의 자원 소유권은 제한이 있다. |
| `video_recognition/` | Windows 창 캡처, 입력 크기 제한, MediaPipe 전체·부분 영역 추론, 후처리·보정 | 참가자 고정 타일을 전제로 하지 않는다. 화면 경계 기반 후보 영역도 추가 분석한다. 작은 얼굴·중복 제거·실제 다인 정확도는 검증되지 않았다. |
| `engagement_model/` | 단일 얼굴 Gaussian 상태 계산, ID/임시 위치별 보정·집계, `WindowPublisher` | 현재 프런트·Windows 데모는 머리 점수를 집계하고 눈 점수는 별도 참고값으로 계산한다. `latest` 계산과 `engagement_window` 발행이 실제로 연결되어 있다. |
| `integration/` | 계약 검증, 공통 시간축, 전사 revision, 근거 연결, JSON 저장·재열기 | RLock과 복사 반환, 임시 파일·원자 교체를 사용한다. 기존 v0.1.0과 현재 v0.2.0 확장안을 읽는다. |
| `sherpa_stt/` | 루프백/마이크 → 메모리 큐 → 스트리밍 인식 → 부분·확정 전사 | 세션 공통 시계와 청크 누락 처리가 연결되어 있다. 프로세스 루프백 도우미는 별도 실험 경로다. |
| `faster_whisper_stt/` | 콘솔 비교와 선택형 `WhisperLiveTranscription` | 현재 프런트는 base/small 선택형 경로도 연결한다. 기본 10초 비중첩 확정 전사로, sherpa의 실시간 부분 전사와 지연 특성이 다르다. |
| `ai_agent/` | PDF/PPTX 텍스트 → 로컬 BM25 → 점수·전사 기반 제안과 사후 피드백 | 로컬 검색 및 외부 작성기를 지원한다. 근거 ID·자료 페이지를 연결한다. 외부 API 결과의 사실 정확성은 검증하지 않는다. |
| `experimental_vision/` | 공통 영상 코드의 모의 회귀 테스트 | 일부 테스트가 이전 데모 구조와 이전 축소 규칙을 참조하고 있어 현재 진입점에 맞췄다. |

실행은 가상환경에서 `python -m streamlit run frontend/app.py`로 시작한다. 모델 준비 후 세션을 만들고, 영상 특징과 오디오 청크를 각 작업에서 처리한 뒤 공통 서비스에 결과 이벤트만 전달한다. 종료 시 생산자를 정리하고 마지막 구간을 발행한 뒤 세션을 종료·저장한다. 재열기는 종료된 기록을 복원하며 실시간 수업을 재개하지 않는다.

설계상 캡처·특징·점수·이벤트의 경계는 유용하다. 다만 모델·개발자 표시·CLI 사이의 결합이 있고 문서 일부가 실제 결선보다 오래되어 있었다. 자동 보정이 실제 정면을 보장하거나 실험 점수가 집중도·이해도를 측정하는 것은 아니다. 제안서의 정확도·CER·지연·10분 연속 실행 목표는 달성 결과로 간주하지 않는다.

의존성은 통합 영상·프런트·STT·조교별 requirements로 나뉜다. 이 환경의 Python은 3.14.3이다. 기존 `video_recognition/requirements.txt`는 구형 EyeGestures 환경이므로 통합 환경의 requirements와 합쳐 설치하면 안 된다. 설치 버전의 보안 취약점 유무를 온라인 자문 DB로 대조하는 감사는 실시하지 않았다.

## 2. 확인하고 수정한 문제

Critical로 확정할 근거는 없었다. 발생 가능성은 코드 경로와 사용 조건 기준의 정성 평가다.

| 우선순위 | 위치·원인 | 영향·발생 조건 | 적용 및 기대 효과 | 난이도·위험 |
|---|---|---|---|---|
| High | `integration/service.py`, `contracts.py`: 금지 키 검사가 이벤트에만 적용되고 튜플 내부는 검사하지 않음 | 설정이나 가져온 JSON의 메타데이터에 알려진 원본 데이터 키를 넣으면 저장 경계를 우회할 수 있음. 비정상 입력 시 재현 가능 | 세션 설정·가져온 파일 전체와 튜플 내부도 검사. NaN/Infinity 설정도 등록 전에 거부 | 낮음. 원래 저장 금지였던 입력이 새로 거부됨. 정상 확장 필드는 유지 |
| High | `frontend/live_session.py`: 모델 정보가 실제 생성기와 별도로 하드코딩됨 | 현재 머리 전용 모델 결과에 과거 머리·눈 모델 버전이 설정·상태로 남음. 기본 사용에서 발생 | `group_model_identity()`를 생성기·세션 설정·상태가 공유하여 재현·출처 정보 일치 | 낮음. 이벤트 형식과 점수 계산은 유지 |
| High | `frontend/app.py`, `dashboard_data.py`: 삭제가 일반 JSON만 제거함 | 복구본이 남은 세션은 삭제 후 복구 목록에 다시 나타날 수 있음 | 복구본과 일반 파일 함께 삭제. 복구본 삭제 실패 시 일반 기록 유지. 같은 ID가 진행 중이면 종료 후 삭제 | 낮음. 별도 다운로드 파일·진단 로그는 범위 밖 |
| High | `ai_agent/assistant.py`: 외부 요청 전후에 종료 상태를 검사하지 않음 | HTTP 응답이 종료 뒤 도착하면 실시간 제안을 사후 이벤트로 발행하거나 후속 외부 검색을 시작할 수 있음 | 종료·취소를 요청 전후와 발행 전에 검사하여 늦은 결과와 후속 요청 차단 | 중간. 진행 중인 HTTP 요청 자체를 강제 취소하지는 않음 |
| Medium | `faster_whisper_stt/runner.py`: `WhisperConfig` 입력 검증 없음 | `window_seconds=0`이면 `take=0`, offset 불변인 반복이 가능함. 잘못된 코드 설정에서 발생 | 양의 정수 길이·스레드 수, 16kHz와 모델명 검증을 생성 시 수행 | 낮음. 기본 UI 설정은 동일 |
| Medium | `ai_agent/writer.py`: SDK 경로는 응답 검사와 선택 패키지 누락 처리 부족 | 형식이 틀린 외부 응답이나 anthropic 미설치가 후속 로직 예외로 이어질 수 있음 | 개인 API 경로와 같은 응답 검사 적용, ImportError도 기존 대체 처리로 전달 | 낮음. 정상 응답은 동일 |
| Medium | `ai_agent/assistant.py`: 실시간 외부 생성 실패 시 자료가 있어도 바로 반환 | 문서상 제공하는 로컬 자료 검색 대체 경로가 실시간 분기에서 동작하지 않음 | 관련 자료가 있으면 로컬 `resource_suggestion`으로 대체. 로컬 provenance를 기록하고 AI 생성으로 표시하지 않음 | 낮음. 자료 없는 실패는 기존처럼 제안 보류 |
| Medium | `integration/service.py`: 제안·피드백을 개별 깊은 복사한 뒤 전체를 다시 깊은 복사 | 전체 스냅샷 조회마다 중복 연산. 제안·피드백 누적 시 발생 | 중간 객체는 얕은 사본, 반환 직전에 한 번 깊은 복사. 반환값 격리는 유지 | 낮음. 중첩 데이터 수정 회귀 검사 통과 |
| Medium | `video_recognition/window_capture.py`: 공유 캐시가 일시정지 뒤 마지막 원본 프레임 참조를 유지 | 연결을 닫아도 Python 측 이미지 메모리가 남음. 콜백과 close 경합 시 재보관 가능 | close에서 프레임 해제, 콜백은 잠금 안에서 정지 상태 재검사 | 낮음. 네이티브 중지·재사용 정책은 변경하지 않음 |

| Medium | 테스트의 오래된 생성기 패치·고정 출력 기준 | 현재 기능 변경과 테스트 실패 원인을 혼동하고 회귀 신호를 잃음 | 기존 0.3초 기준 비교 테스트는 설정을 명시해 보존. 현재 기본값 0.5초는 되돌리지 않음. 새 데모 진입점·진단 필드·응답 계약으로 테스트 갱신 | 낮음. 기준 해시를 새 출력으로 덮어쓰거나 검사를 건너뛰지 않음 |

주요 수정 파일은 표의 구현 파일과 각 모듈 테스트다. 루트 README, `frontend/README.md`, `engagement_model/README.md`, `ai_agent/README.md`, `faster_whisper_stt/README.md`, `video_recognition/README.md`, `integration/update.md`도 관련 동작에 맞춰 갱신했다. 계약 버전·이벤트 필드·JSON 최상위 구조는 변경하지 않았다.

## 3. 검증 결과

저장소 루트에서 `video_recognition/.venv/Scripts/python.exe -B -m unittest`에 다음 인자를 붙여 실행했다.

| 인자 | 결과 |
|---|---|
| `discover -s integration/tests -t .` | 6개 통과 |
| `discover -s engagement_model/tests` | 132개 통과 |
| `discover -s frontend/tests` | 59개 통과 |
| `discover -s sherpa_stt/tests -t .` | 31개 통과 |
| `discover -s ai_agent/tests -t .` | 34개 통과 |
| `discover -s faster_whisper_stt -p test_*.py` | 11개 통과 |
| `discover -s experimental_vision` | 46개 통과 |
| `video_recognition.test_window_enumeration video_recognition.test_layout_regions` | 7개 통과 |

총 326개. 카메라·네트워크 API는 모의 객체를 사용하는 테스트를 포함한다. 테스트 중 손상 PDF 입력 경고와 Streamlit 실행 컨텍스트·구 API 경고가 출력되며 실패는 아니다.

- 변경 전 모델 2건, 프런트 4건, sherpa 1건, 조교 2건 실패를 관찰했다. 확장 검사 중 실험 영상에서도 과거 데모·축소 기준을 참조하는 3건 실패를 확인하고 수정했다.
- `python -m pip check`: `No broken requirements found.` 이는 의존성 메타데이터 검사이며 취약점 검사나 모든 선택 패키지 설치 보장은 아니다.
- 프로젝트 8개 코드 디렉터리의 Python 파일 110개를 `ast.parse`로 검사했다. 가상환경·모델·캐시는 제외했다. 구문 오류가 없었다.
- `git diff --check`: 공백 오류 없음. 기존 파일의 CRLF 변환 안내는 별개다.
- ruff·mypy·pyright가 설치되지 않아 전용 정적·타입 검사는 실행하지 않았다. 별도 프런트 번들 빌드 설정은 없으며 Streamlit 화면은 기존 AppTest로 확인했다.

### 성능 측정

같은 Python 프로세스에서 변경 전 서비스(`git show fac560d:integration/service.py`, 해당 파일은 작업 시작 당시 깨끗했음)와 변경 후 서비스에 동일한 종료 세션 상태를 넣었다. 합성 전사 600개·메모 200개·피드백 200개·초기 상태 1개, 합계 1,001개 이벤트를 사용했다. 스냅샷 반환값 동등성을 먼저 확인하고 `timeit.repeat(number=10, repeat=7)`로 측정했다.

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 스냅샷 1회 소요 시간, 7개 배치의 중앙값 | 6.105ms | 5.047ms |

이 조건에서 약 17% 단축했다. 제안·피드백 구성과 장치에 따라 효과가 달라지며, 영상 추론·UI 표시·실제 수업 전체 지연의 개선으로 확대 해석하지 않는다.
