# 라이브 대시보드 개선 지시와 검증

## 실행한 작업 프롬프트

> 현재 성능 로그와 Streamlit 라이브 화면의 갱신 흐름을 분석한다. 점수·보정, 분석 상태·도구, 타임라인, 전사, 메모, 조교 제안을 2열·3행의 일정 높이 카드에 압축 배치한다. 긴 내용은 카드 내부에서 확인하게 한다. 개발자 창과 로그 수집의 시작·중지가 카드 구조·기존 내용·입력 중 메모·그래프 범위를 바꾸지 않도록 한다. 관측 불가를 0점으로 바꾸지 않고 원본 데이터·개인별 특징을 추가 저장하지 않는다. 재현한 결함과 추정 원인을 구분하고 자동 회귀 검사를 수행한다. 실제 브라우저 확인이 막히면 코드·화면 구조 테스트를 계속하며 미검증 범위를 명시한다.

## 로그에서 확인한 내용

`frontend/diagnostic_logs/`의 최근 성능 JSONL 5개를 읽었다. 원본 로그와 세션 JSON은 수정하지 않았다. 아래 수치는 기존 기록의 요약이며 이번 UI 수정의 성능 측정값이 아니다.

| 로그 파일 접두 시각(UTC) | 표본 | 영상 Hz 중앙값 | STT 처리 지연 중앙값 / 최대 | 큐 최대 / 버린 청크 |
|---|---:|---:|---:|---:|
| `20261114T165017Z` | 23 | 7.78 | 1,170 / 13,098ms | 112 / 0 |
| `20261114T165336Z` | 11 | 영상 꺼짐 | 852 / 2,768ms | 11 / 0 |
| `20261114T170159Z` | 15 | 8.04 | 3,532 / 4,202ms | 44 / 0 |
| `20261114T171607Z` | 48 | 7.23 | 1,779 / 5,514ms | 48 / 0 |
| `20261115T054024Z` | 10 | 5.92 | 2,561.5 / 5,047ms | 45 / 0 |

- 최신 파일의 CPU 중앙값은 논리 코어 하나를 100%로 잡았을 때 259.5%, 프로세스 작업 집합 최대는 약 792MiB였다. 영상 분석 간격 중앙값은 148.5ms, 최대 316ms였다. 입력 처리 부하와 대기는 관찰되지만 메모리 누수나 UI 소실의 원인을 이 짧은 기록만으로 확정할 수 없다.
- `171607Z` 기록에는 개발자 프리뷰의 꺼짐→켜짐→꺼짐 전환이 있었다. 그 전환 표본의 영상·모델·STT·조교 상태는 모두 실행 중이었다. 세션 끝부분의 영상·모델 종료 기록은 별도다.
- 성능 로그에는 브라우저 DOM, 카드 표시 여부, 화면 재실행 원인이 없다. 따라서 로그만으로 카드가 사라진 사실이나 네이티브 창과의 인과관계를 확인할 수 없다. STT 지연 수치도 발화에서 화면 표시까지의 전체 지연이 아니다.

## 재현과 수정

1. **메모 초안 소실 재현:** 입력값을 저장 버튼 전까지 서버로 제출하지 않는 `st.form` 안에 메모 입력이 있었다. 도구 전환 회귀 테스트에서 입력 중 메모가 빈 문자열이 되었고 이후 저장도 누락되었다. 일반 입력 상태로 옮기고 명시적 저장 버튼에서만 계약 이벤트를 추가하도록 수정했다. 저장 성공 후에만 초안을 비운다.
2. **전체 화면 재실행 축소:** 개발자 도구는 전체 앱 `st.rerun()`을 요청하고, 요약과 진단은 각각 주기 갱신했다. 도구·재보정·메모·제안 동작을 콜백으로 바꾸고 라이브 화면 전체를 하나의 fragment로 갱신한다. 진단은 같은 스냅샷을 받는 일반 출력 함수로 분리했다.
3. **배치가 실행 상태에 의존하지 않도록 수정:** 기존 CSS는 `stStatusWidget`의 label/button 존재 여부에 따라 본문 여백과 제목 위치를 변경했다. 실행 상태 표시를 화면 배치 조건으로 사용하지 않도록 해당 선택자를 제거했다. 이 조건이 실제 브라우저의 전체 내용 소실까지 일으켰는지는 미검증이다.
4. **고정 카드:** 각 카드에 고정 key와 높이를 지정한다. 빈 상태·오류·긴 전사·제안·로그 경로가 있어도 카드 바깥 크기는 유지한다. 내용이 넘치면 카드 내부를 스크롤한다. 2열을 기본으로 하며 540px 이하에는 한 열로 전환하는 CSS를 둔다.

| 행 | 왼쪽 | 오른쪽 | 카드 높이 |
|---|---|---|---:|
| 1 | 점수·경과 시간·정면 보정 | 최신 조교 제안·출처·이전 제안 | 170px |
| 2 | 시간 범위 선택·타임라인 | 최근 확정 전사·부분 전사·이전 전사 | 250px |
| 3 | 메모 초안·저장·최근 메모 | 구성요소 상태·전사 지연·대기열·영상 주기·개발자/로그 버튼 | 210px |

개인별 임시 진단 표와 자세한 품질·음량·손실 설명은 아래 **분석 상세 상태**에 유지했다. 점수·상태·메모 이벤트의 계약과 모델 계산은 변경하지 않았다. 개발자 프리뷰나 성능 로그 수집이 영상·음성 분석 설정을 바꾸지도 않는다.

## 검증

저장소 루트의 `video_recognition/.venv/Scripts/python.exe`로 실행했다.

- `-B -m unittest discover -s frontend/tests`: 요약 카드 배치 회귀 검사를 포함한 70개 통과.
- `-B -m unittest discover -s integration/tests -t .`: 저장 경계와 스냅샷 격리 6개 통과.
- 신규 AppTest는 카드 key·높이·3개 행의 동일 너비 2열, 도구 네 번 전환 후 초안·범위·세션·카드 보존, 명시적 전체 rerun 미호출, 로그 시작 실패 시 화면 유지, 메모 단일 저장, 긴 전사/빈 세션, 제안 저장의 근거 유지, 수업 종료·저장·사후 검토 전환을 검사한다.
- 화면 구조 검사는 Streamlit이 생성한 블록과 위젯 상태 기준이다. 브라우저 픽셀 렌더링과 실제 네이티브 프리뷰 동작을 대체하지 않는다.

브라우저 연결 호스트가 사용할 수 없는 상태여서 실제 Chrome의 픽셀 배치, 좁은 창에서의 스크롤·반응형 전환, 실제 분석 중 개발자 창/로그 전환을 직접 확인하지 못했다. 신규 미디어 캡처·외부 AI 호출·개인 데이터 저장은 수행하지 않았다. 실제 장치에서는 준비된 동의 세션에서 도구 두 종류를 각각 켰다 끄고 카드 내용과 메모 초안이 유지되는지 최종 확인해야 한다.

## 사용자 스크린샷의 텍스트 겹침 보완

후속 스크린샷에서 카드 제목·설명·버튼의 겹침을 확인했다. 초기 압축 CSS는 내부 `stVerticalBlock` gap을 `0.35rem`으로 바꾸면서 Streamlit에는 다른 간격 설정이 남아 있었고, h3 padding/margin과 설명의 줄 높이도 별도로 재정의했다. 블록 구조 검사만으로는 이 실제 픽셀 문제를 검출하지 못했다.

라이브 전용 간격·글자 크기·줄 높이·여백·버튼 최소 높이 재정의를 제거하고, 6개 카드 모두 Streamlit의 공식 `gap='xsmall'` 설정으로 압축 간격을 지정했다. 고정 카드 높이와 2열 구성은 유지한다. 새 테스트는 6개 카드에 실제 gap 설정이 전달되는지와 충돌했던 CSS 재정의가 없는지 검사한다. 수정 후 실제 브라우저의 픽셀 확인과는 구분한다.

후속 배치 요청에 따라 조교 카드는 오른쪽 위, 분석 상태·개발자 도구는 오른쪽 아래로 교환했다. 카드 배경만 흰색으로 지정하고 간격·줄 높이 설정은 유지했다.

## 왼쪽 위 요약 카드만 재배치

첨부된 화면에서 점수의 중첩 테두리·여백과 본문 오른쪽의 큰 종료 버튼 때문에 재보정 버튼과 점수 사유가 카드 아래로 밀리는 것을 확인했다. 카드 전체를 키우는 방식은 다른 행의 위치도 바꾸므로 선택하지 않았다.

기존 170px 높이를 유지하고 다음과 같이 세 영역으로 나눴다.

- 상단: 수업 상태·경과 시간, 작은 수업 종료 버튼. 긴 수업 제목은 시간 표시의 도움말에 둔다.
- 본문: 왼쪽은 테두리·추가 여백 없는 점수, 오른쪽은 보정 상태와 재보정 버튼.
- 하단: 전체 너비에 한 줄 점수 사유. 전체 설명과 이전 참고값은 같은 줄의 도움말로 확인한다.

이 카드와 보정 영역만 Streamlit의 공식 `xxsmall` 간격을 사용한다. CSS로 내부 gap·줄 높이를 덮어쓰지 않았으며 다른 다섯 카드의 배치·높이는 변경하지 않았다. 자동 검사는 상단·본문·하단의 위젯 위치, 수집 중 상태, 긴 제목의 도움말, 기존 도구 전환·저장 동작을 확인한다. 실제 브라우저 픽셀 재확인과는 구분한다.

### 종료 버튼을 카드 밖으로 분리

후속 스크린샷에서 카드 안의 종료 버튼이 세로 공간을 차지하며 스크롤을 유발하는 것을 다시 확인했다. 종료 버튼을 페이지 제목 오른쪽의 독립 헤더 영역으로 옮겼다. 요약 카드의 높이 170px, 점수·보정 두 열, 나머지 카드 위치·높이는 유지한다. 회귀 검사는 종료 버튼이 요약 카드에 없고 헤더 오른쪽에 있으며 종료·저장·사후 검토 전환이 유지되는지 확인한다.
